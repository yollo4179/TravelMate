# 관찰 경계 분할·이동 관계·검수 후 선택

문서 버전: 1 · 실행·작성: 2026-11-01 · 구현 기준: `2486be9a`의 후속 작업

**분할과 관계 표현은 구현했다. 자동 판정은 고정 사례 5개 중 4개 통과이며, 다른 장소 경관의 귀속 오류가 남았다.**
검수에서 잘못된 후보를 승인하지 않은 뒤의 선택은 5개를 만족했다. 이를 Sonar의 자동 판정 5/5로 표시하지 않는다.
기본 프롬프트 v2·기존 분할·검색 근거 기본 1개를 유지하며 운영 DB 적용·배포는 하지 않았다.

## 수정한 구조

1. 서버가 문장 종결·문단·제목·구분선에서 원문을 나눈다. 장소 이름 수로 나누지 않는다.
2. 같은 문장에 있는 A→B 이동은 하나로 보존한다. 정확한 원문·위치·출처·별도 분할 버전을 기록한다.
3. Sonar는 새 구간마다 문맥·장소 역할·내용 종류를 새로 판정한다. 부모 청크의 문맥·역할을 복사하지 않는다.
4. 경관·시설과 이동을 구분한다. 이동은 출발지·도착지·현재 원문의 조건 인용을 구조화한다.
5. 불명확·검증 오류 구간은 원본과 함께 보존한다. 명시적 검수 목록에 승인된 구간만 적용할 수 있다.
6. 검수 후 장소별 기존 20개 제한과 출처 순회·중복 제거 선택을 적용한다.

관찰 경계를 완전히 이해하는 자동 분할기는 아니다. 문장·문단 휴리스틱이므로 한 문장에 남는 혼합 관찰과 잘게 잘린 대명사·시설 설명은 재귀속·검수가 필요하다.
경계가 없는 긴 문장을 800자에서 임의로 자르지 않고 준비 단계에서 거부한다.

| 항목 | 선택 계약 |
|---|---|
| 분할 | `sentence-paragraph-v2`, 기존 기본값은 `source-span-v1` |
| 입력 | 기존 명시적 원문 `source-explicit-chunks-v2` |
| 프롬프트·출력 | `contextual-observation-relations-v6`, 새 스키마 |
| 내용 종류 | `landscape / facility / movement / other` |
| 장소 역할 | 기존 `subject / mentioned / view_target`, 내용 종류와 별개 |
| 이동 관계 | `origin / destination / conditions`, 미등록 endpoint ID는 `null` |
| 처리 | `contextual-validation-v3`, 오류 구간 격리와 이동 보류 |
| 검수 | `contextual-approval-v1`, 원본 4개 파일 해시에 묶인 승인 ID |

이동의 등록된 양끝은 핵심 참가자로서 subject가 될 수 있다. 이는 두 장소의 경관·시설을 공유시킨다는 뜻이 아니다.
내용 종류와 이동 방향 필터를 사용하면 관계 청크를 경관·주차 근거로 우회시키지 않는다.
조건 인용이 원문에 있다는 검사는 의미·방향까지 보증하지 않는다. 계단·거리·시간만으로 ‘쉽다·안전하다’를 만들지 않는다.

## 실제 생성과 처음 중단된 이유

전체 9개를 다시 생성하지 않고 회귀가 있는 **P08·P09 두 묶음**을 선택했다.
원문·장소 목록·모델 선택·`fast`·8192 출력 한도·`tools=[]`를 유지했다.
기존 v5의 5구간을 새 57구간(P08 29, P09 28)으로 나눴다. 실제 모델은 양쪽 모두 `perplexity/sonar`다.
분할·지시문·출력 스키마·처리 규칙이 함께 바뀐 계약 검수이며 분할만의 효과로 해석하지 않는다.

첫 P08 응답은 공급자 상태 `completed`로 도착했지만, 미등록 ID와 endpoint 명칭 불일치 때문에 처음 처리 버전 v2에서 전체가 `FAILED`로 보존됐다.
P09 호출은 그때 중단했다. 원본을 고치지 않고 처리 v3에서 P08을 **무료 재검증**했다.
정상 구간을 보존하고 오류 구간을 격리한 뒤 아직 호출하지 않은 P09만 1회 실행했다. P08 재생성은 없었다.

전체 스키마·원문 위치의 누락·중복·변조는 여전히 응답 오류다.
그 검사를 통과한 뒤 귀속 ID·관계 명칭·조건 인용 오류만 구간별로 격리한다.
구체적 관계가 없는 이동은 `unresolved_movement`, 주체가 불명확하면 귀속 보류로 남긴다.
미등록 ID를 대상 ID로 바꾸거나 문맥·관계를 자동으로 고쳐 성공 처리하지 않았다.

| 처리 결과 | P08 | P09 | 합계 |
|---|---:|---:|---:|
| 생성 구간 | 29 | 28 | 57 |
| 형식·귀속 검증 후 후보 | 11 | 22 | 33 |

‘귀속 검증 오류’ 10구간에는 미등록 ID뿐 아니라 등록 ID와 endpoint 명칭 불일치도 포함된다.
여기서 미등록은 입력으로 제공한 장소 목록 밖이라는 뜻이며, 해당 숫자가 운영 DB 어디에도 없다고 확인한 것은 아니다.
자동 검증을 통과한 후보 33개가 의미적으로 모두 맞는 것은 아니었다.

## 고정 회귀 5개

생성 전에 원문 source/version/위치와 기대 역할·종류를 고정했다.
기존 **P08-S01**은 `P08-view-owner`와 `P08-transition`으로 관찰·이동 범위를 각각 고정했다.

| 사례 | 자동 후보 판정 | 검수 후 선택 |
|---|---|---|
| P08 다른 공원 전망을 대상에 연결하지 않음 | 통과 | 유지 |
| P08 계단을 이용한 대상 공원으로의 이동 보존 | 통과 | 선택 |
| P08 주말·공휴일 주차 혼잡 근거 | 통과 | 선택 |
| P09 무료 주차 근거 | 통과 | 선택 |
| P09 다른 공원의 한강 경관을 대상에 연결하지 않음 | **실패** | 미승인으로 제외 |

P08의 전망은 귀속을 보류했고, 계단 이동은 한 구간의 관계로 남았다.
이 실제 자료에는 출발지의 등록 ID가 없어 `null`로 보존했다. 임의 ID를 만들지 않았다.
등록된 양끝의 방향 검색은 별도 합성 자료로 코드·SQL을 검증했다.

P09-N015는 여전히 다른 공원 경관을 청담도로공원 subject로 설명했다.
같은 이동 뒤의 정원·시설·휴식 관찰도 장소 범위가 잘못되거나 불명확해 승인하지 않았다.
P09-N028은 출차 조건이 진입 관계에 함께 붙어 방향 범위가 불명확하므로 보류했다.
자동 모델의 귀속·관계 판정이 해결됐다고 보지 않으며 검수 단계가 오류를 막은 결과를 따로 기록한다.

분할이 지나치게 잘면 유효한 시설 설명도 귀속을 보류할 수 있다. P08의 정자·기념비 설명 등은 남아 있지만 검색 후보에서는 제외됐다.
고정 5사례 외의 모든 유효 근거가 검색에 보존됐다고 주장하지 않는다.

## 20개 선택과 검색 구현 범위

두 묶음의 승인 생성 구간 20개와 TourAPI 1개를 합친 **21개를 메모리에서 20개로 선택**했다.
선택에는 생성 구간 19개·TourAPI 1개가 포함됐다. 고정한 이동·주차 근거는 남았고,
탈락한 1개는 이미 24시간 안내와 중복되는 기사 마지막의 방문 가능 문장이다.
전체 9개·운영의 다른 보강 자료를 동시에 활성화한 실험은 아니다. DB에 이 목록을 적용하지 않았다.

워커의 `filters.observation`은 내용 종류와 이동 방향을 명시적으로 제한한다.
목적지 B와 결과 endpoint `origin`을 지정하면 A→B의 출발지를, 출발지 A와 결과 `destination`을 지정하면 도착지를 찾는다.
후보 검색과 복수 근거 확장에 같은 조건을 적용하고, 해당 근거가 없으면 일반 장소 설명으로 우회하지 않는다.
미등록 endpoint를 새 장소 결과로 만들지 않는다. ‘다른 장소’ 검색에서는 기존 제외 ID 조건으로 기준 장소를 제외할 수 있다.

이 필터의 자연어 자동 선택·Spring 도구/DTO·UI 연결은 구현하지 않았다.
실제 임베딩·리랭킹 검색 결과, 전체 서비스 지연, 전체 출처 동시 색인 D는 측정하지 않았다.
