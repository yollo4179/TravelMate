# 평가 도구 계약·관측·호출 상한 정리

후속 회귀 수정: [동결 반경 문항의 중심 장소 ID 처리](center-place-id-regression-20261102.md).
아래 125개 검증은 최초 정리 기록이며, 후속 수정에서는 기존 85문항의 요청 변환과 전체 회귀 131개를 확인했다.

기준: `develop`의 `b8e793c397f9eba547191692de814901946d059c`.
작업 브랜치: `chore/evaluation-tool-contracts`.
코드 검증 커밋: `6f08c6228a6ccf05d536c64d5c850cb1a057209c`.

이 변경은 보존된 평가 도구를 최신 검색 API와 관측 처리에 연결한 것이다.
실제 모델·검색·LangSmith 조회/게시·Docker/DB 명령은 실행하지 않았다.
GitHub 브랜치 푸시와 PR 작성은 이 실행 제한과 별도의 사용자 요청이다.
모의 회귀 통과를 검색·도구 선택·계획·설명의 실제 품질 완료로 표시하지 않는다.

## 원본과 관측의 보존

- `http_request.raw_body`와 해시, 원래 조건, 별도 평가용 projection을 보존한다. 검색어·필터를 추측하거나 원문을 절단하지 않는다.
- 검색 결과의 장소 ID와 전체 `evidenceChunks`·원문·출처·귀속·관계·조건을 응답 그대로 유지한다.
- 성공한 빈 배열과 HTTP/파싱 실패를 구분한다. 실패한 응답 본문도 보존한다.
- 호출 상한·미지원 조건·이전 실패 이후에는 추가 전송 없이 `not_run`으로 남긴다. 선택된 원래 입력도 별도 저장한다.
- harness attempt ID, 공급자 HTTP request ID, completion ID, 서버가 실제 반환한 ID를 구분한다. 없는 turn/Job/tool_calls/LLM 설명은 만들지 않는다.
- provider 전략·대상 URL·모델·원본 인자·원본 응답·usage·시각·시간·종료 상태를 남긴다. 없는 usage는 0으로 확정하지 않는다.
- 기존 native 도구 원본/변환, MOCK 분모 제외, Job 접수와 DRAFT 완료의 구분을 유지한다.
- 과거 검색 기록에 부족한 관측을 자동 보충하지 않는다. 명시적인 호환 변환 없이는 새 품질 기록으로 채점하지 않는다.

## 실행 설정

[검색 평가 도구 계약](../../Evaluation/tracks/search/README.md)에 CLI와 필수 설정을 기록했다.
새 LIVE 설정·대상 모델·실제 case 목록·반복·비용을 이번 작업에서 선정하거나 승인하지 않았다.

공통 설정은 mode, case_ids, max_calls, timeout_seconds, model, max_output_tokens, parameters를 명시한다.
MOCK는 정확한 요청 해시의 fixture가 필수이며 실제 전송 함수와 API client를 사용하지 않는다.
LIVE와 MOCK를 섞거나 기존 journal로 예산을 초기화하는 재시작을 허용하지 않는다.
실패·시간 초과도 호출 시도 상한을 소비하고, 첫 실패 이후 추가 외부 호출을 중단한다.
여기서 전송 시도 수는 서버가 실제 추론을 완료했다는 증거가 아니다. 성공·usage는 별도 응답 관측이다.

후보 judge의 독립 판정·중재 여부는 설정에 명시돼야 한다.
독립 판정 2회 또는 중재를 포함한 최대 3회 × 선택 case 수를 실행 전에 대조한다.
조건 감사는 보존된 case별 조건표와 명시된 배치 크기에 따른 호출 수를 검사한다.
공통 설명 judge도 `--execution-config` 없이는 호출하지 않는다.
[공식 OpenAI SDK 문서](https://developers.openai.com/api/reference/python#retries)에 따라 `max_retries=0`을 설정하고 애플리케이션 보정 루프도 제거했다.

LangSmith는 개별 HTTP 요청을 직접 계산해 SDK 내부 묶음 전송·재시도를 피한다.
숫자 feedback N개의 게시 상한은 publish `1+N`, observation_read `1+N`이다.
명시한 새 run 생성, feedback 생성, 각 원본 재조회가 이에 해당한다.
HTTP 오류·재조회 불일치는 부분 실패로 기록한다. 자동 수정/재게시/삭제는 하지 않는다.
과거 배치 보고서는 `legacy_report_only`로 보관하며 검증된 현재 품질 feedback으로 바꾸지 않는다.

## 오프라인 검증

별도 LF 체크아웃에서 다음 명령으로 **125개·실패 0·오류 0**을 확인했다. 소요 시간은 13.630초다.

```powershell
python -X utf8 -m unittest discover -s Evaluation/tests
```

이 중 새 검색/대상/실패 관측 회귀는 20개, bounded judge 회귀는 9개, bounded 게시/집계 회귀는 11개다.
보존한 후보·조건·잠정 비교 검사와 기존 native 관측·평가기 검사도 함께 통과했다.
실제 API adapter 검사는 `httpx.MockTransport` 또는 모의 응답을 사용한다.
일부 회귀는 LIVE 형식의 합성 receipt로 차단/인자 계약을 검사하지만 실제 LIVE 실행 기록이 아니다.

초기 Windows 체크아웃에서는 당시 전체 검사 124개 중 아카이브 보존 검사 1개가 실패했다.
`Evaluation/datasets/v1.1.0/.gitattributes`의 CRLF 바이트가 원인이다.
정규화한 Windows 내용 = Git blob = 별도 LF 체크아웃 바이트임을 확인했다.
동결 파일·manifest·저장소의 줄바꿈 설정을 고치지 않고, `git -c core.autocrlf=false worktree add --detach ...`로 분리해 재검증했다.
후속 관측 회귀를 추가한 최종 전체 검사 수가 125개다.

[검증 JSON](evaluation-tool-cleanup-20261102.validation.json)에 코드 SHA, 건수, 줄바꿈 대조, 15개 동결 파일 해시와 원본 83개 보존 결과를 남겼다.
15개 파일은 원본·백업·브랜치 Git blob·LF 체크아웃에서 모두 같은 바이트다.
기존 corpus·snapshot·역대 golden 해시도 그대로다.
보존한 83개 원본/백업의 해시와 원래 작업 상태는 변하지 않았다.

## 남은 한계

1. 실제 검색·모델의 도구 인자·답변 근거 일치·순위 품질·GPU 지연은 재측정하지 않았다. 모의 회귀는 이를 대신하지 않는다.
2. 실제 Docker/SQL 캡처, OpenAI, LangSmith 계정/API와의 연결은 실행하지 않았다. 이번 LIVE 어댑터는 오프라인 계약 검증 범위다.
3. 캐시 revision과 저장 벡터 지문은 출처 관측이다. 로드된 가중치의 완전 동일성이나 벡터 재계산을 증명하지 않는다. 자료/설정이 미확인·불일치면 순위 비교 가능으로 표시하지 않는다.
4. 최신 검색은 원문/청크/관계를 쓸 수 있다. 과거 단일 description 실험을 현재 전체 검색과 같은 입력·설정이라고 보지 않는다.
5. 실제 trace/span/종료 시각·장치·정밀도가 없으면 미관측이다. CPU/GPU, FP32/autocast 설정을 같은 지연 그룹에 섞어 개선이라고 하지 않는다.
6. AI 판정은 사람 검수 완료가 아니다. 인용 일치 검사도 의미 판단의 정답을 보증하지 않는다. unknown·MOCK·실패·미실행은 품질 분모에서 제외한다.
7. 계획 조건 준수·실제 이동시간/동선 최적화·수정/확정/롤백은 이번 범위에서 완성하거나 새로 평가하지 않았다.
8. 실제 실행 전에는 대상·case·반복·상한·예상 비용/지연·중단 조건을 다시 제시하고 사용자 범위를 확정해야 한다.

운영 DB 반영·배포·서비스 종료·GPU 배치 변경·기존 기록 삭제는 하지 않았다.
