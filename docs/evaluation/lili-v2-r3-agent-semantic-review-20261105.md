## 구체적인 수정 대상

1. 왕실 거처 추천: 두 번째 컷의 허용 근거 없는 다른 후보 설명을 삭제하고, 원문이 있는 창경궁에 한정해 추천 이유를 말한다. 후보의 이름만 숨기는 방식으로 사실 주장을 통과시키지 않는다.
2. Job 되묻기: ‘조회할 작업 번호를 알려줘’로 안내한다. 이름 조회를 지원하기 전에는 이름만 받으면 조회 가능하다고 약속하지 않는다.
3. Job 실패: ‘일정 생성이 끝나지 못했어’처럼 확인된 상태를 안내한다. 사용자에게 내부 예산·예외 코드를 노출하지 않되, 확인하지 않은 일시적 서비스 장애·재시도 성공 가능성도 단정하지 않는다.
4. 계획: 체류 합과 실제 실행 가능한 총 소요시간을 구분한다. 현재 초안에는 이동시간 미반영과 여유 없음이 드러나게 설명하고, 편안함·효율·최적 동선을 검증한 것처럼 표현하지 않는다. 실제 경로를 측정하지 않았으므로 몇 분을 더 잡아야 하는지는 이 검수에서 추정하지 않는다.

## 기존 검수 도구의 누락

`Evaluation/tracks/conversation/review.py:export_review`는 `score.response_text`만 CSV에 싣는다. LiLi 경로에서 이는 주로 첫 안내 대사다. 최종 추천은 `job_response_text`, 완성 계획은 `records.followed_job.result`에 있어 현재 CSV만 읽으면 핵심 결과를 빠뜨린다.

검수 입력에 최초 안내, 최종 추천 컷, 계획 설명·핀, 해당 단계의 실제 후보 description과 selectedEvidence, 도구가 반환한 상태를 구분해 포함해야 한다. 에이전트 검수 결과는 검수자와 코드·실행 원본을 명시해 기록할 수 있으며 사용자에게 모든 문항의 판정을 전가할 필요가 없다.
