# DRAFT 저장 검증 공통화: 모의 회귀

2026-11-01. 기준 커밋 `86be65091a9ec3cdab81e507629d15492c3d5e27` 후속 변경.
대상은 현재 직접 초안 저장과 LLM 생성이 저장하는 동일한 DRAFT 상태다.
[설계·초안/확정 경계](../../../../../../docs/architecture/draft-plan-validation.md).

## 조사 결과와 구현

기존 직접 저장은 요청·필수 장소 존재/중복/범위·미확인 운영시간 정책을 검사했지만, 체류시간 합과 카페 최소 개수를 검사하지 않았다.
LLM 생성은 결과 검증기에서 체류시간·후보 ID·필수 장소·순서를 검사하고, 서비스에서 카페 개수와 일부 중복 검사를 추가했다.
같은 시간·장소·카페 조건으로도 저장 경로에 따라 결과가 달라질 수 있었다.

- `DraftPlanValidator`에 제목·1~6개 방문·후보 소속·중복·순서·필수 장소·체류시간 합·카페 최소 개수·선택 장소 범위를 모았다.
- 직접 저장이 만든 계획과 기존 LLM 출력에서 파싱한 계획 모두 저장 전에 이 검증을 거친다. LLM 인용 검사는 그 다음에 유지한다.
- `ContextPlanResultValidator`는 JSON 파싱을 담당한다. 생성 서비스의 중복된 장소/카페 검사는 제거했다.
- `PlanAreaValidator`로 기존 거리 계산을 재사용했다. 일반 후보도 저장 전에 검사한다. 검색 SQL·순위·거리 정책 자체는 변경하지 않았다.
- 직접 저장의 검증 실패는 HTTP 400과 해당 사유, 생성 실패는 기존 Job FAILED와 해당 사유로 전달한다. 직접 저장의 작업 실패 사유도 보존한다.

## 같은 계획을 두 저장 경로로 넣은 결과

실제 `ContextPlanningService.create`와 생성 작업 본문 `runGeneration`을 사용했다.
장소 저장소·작업 저장소·검색·LlmClient는 Mockito mock이다. 생성 본문은 ReflectionTestUtils로 동기 실행했으며,
실제 비동기 큐/HTTP/Kafka/DB 통합을 검증한 것은 아니다.
두 경로에 같은 요청과 metadata를 사용하고, 모의 LLM은 직접 저장과 같은 제목·설명·장소·순서·활동을 반환한다.
통과 시 저장소에 전달된 계획이 같은지, 실패 시 저장 호출이 없는지와 생성 작업의 사유가 직접 저장의 사유와 같은지 검사했다.

| 시나리오 | 직접 저장 | 모의 LLM 생성 |
|---|---|---|
| 운영시간 미확인 + ALLOW_WITH_WARNING | 승인 | 승인 |
| 60분 체류, 60분 시간창 | 승인 | 승인 |
| 61분 체류, 60분 시간창 | 거부 | 거부 |
| 두 장소 각각 60분, 120분 시간창, 카페 최소 2 | 승인 | 승인 |
| 두 장소 각각 60분, 119분 시간창 | 거부 | 거부 |
| 카페 최소 1, 선택 장소가 공원뿐 | 거부 | 거부 |
| category는 시설, sourceCategory가 카페 | 승인 | 승인 |
| 카페 최소 2, 선택 카페는 1개 | 거부 | 거부 |
| 필수 장소가 원 밖 | 거부 | 거부 |
| 필수 장소 좌표 미확인 | 거부 | 거부 |
| 미확인 운영시간 EXCLUDE | 거부 | 거부 |
| 중복 필수 장소 | 두 공개 진입점에서 작업 시작 전 거부 | 동일 |
| 존재하지 않는 필수 장소 | 거부·저장 없음 | 동일 |

직접 저장은 선택 목록이 requiredStops이므로, 모델이 필수 장소를 출력에서 빼는 상황을 직접 저장의 출력으로 만들 수는 없다.
그 상황과 모델의 후보 밖 장소·중복 장소·잘못된 순서는 기존 `ContextPlanPipelineTest`에서 공통 검증기에 연결해 검사했다.
생성 일반 후보의 원 밖 좌표, 필수 장소 외 후보의 RELAXED 60분/NORMAL 40분 체류시간 및 정렬, 빈/비JSON 모델 출력도 검사했다.

## 초안에서 허용한 것·확정에서 남은 것

설명·활동·추천 이유 미작성, 목적지 미지정, 실제 방문 시각·이동시간·운영시간 미확인은 초안의 불완전성으로 허용한다.
운영시간은 기존 ALLOW_WITH_WARNING 정책에서만 허용하며 기존 초안 경고를 유지한다.
요청에서 명시한 필수 장소·카페 수·체류시간·중복·범위는 초안에서도 지켜야 한다. 요청의 필수 필드를 새로 완화하거나 빈 계획 저장을 추가하지 않았다.

확정 경로·확정 상태 검증은 **미구현**이다. 실제 이동을 포함한 시간 성립·운영시간/방문 조건 확인 정책도 향후 과제다.
체류시간 합이 시간창 이내라는 결과를 실제 이동시간·도보 가능성·최적 동선의 검증으로 해석하지 않는다.
예산·고정 방문 시각·지원 밖 이동 수단 등 기존 지원 제한은 유지한다.

## 실행·결과

`Server/TravelMate`에서 오프라인으로 실행:

```powershell
.\gradlew.bat --offline test `
  --tests com.yollo.TravelMate.DraftPlanValidationTest `
  --tests com.yollo.TravelMate.SearchEvidencePipelineTest `
  --tests com.yollo.TravelMate.ContextPlanPipelineTest `
  --tests com.yollo.TravelMate.PlanContextContractTest `
  --console=plain
```

| 테스트 클래스 | 통과 | 실패/오류/건너뜀 |
|---|---:|---:|
| DraftPlanValidationTest | 18 | 0/0/0 |
| SearchEvidencePipelineTest | 7 | 0/0/0 |
| ContextPlanPipelineTest | 2 | 0/0/0 |
| PlanContextContractTest | 2 | 0/0/0 |
| 합계 | **29** | **0/0/0** |

파라미터화된 개별 실행을 포함한 JUnit 테스트 수다. 기존 평가 데이터셋의 질문 수나 실제 여행 품질 평가 문항 수가 아니다.
원문·출처·귀속·관계·부정/상충 정보의 전달 및 전달된 근거에 대한 인용 소속 검사는 기존 7개 회귀로 유지했다.
의미적으로 맞는 설명인지, 실제 모델이 조건을 잘 지키는지까지 통과로 세지 않는다.
[JUnit 결과](junit/)와 [집계·보존 파일 확인](verification.json)에 실행 결과와 SHA-256을 남겼다.
공개 파일과 비교할 수 있도록 JUnit 줄바꿈과 소스 해시는 UTF-8/LF 기준으로 정규화했다. 테스트 내용은 변경하지 않았다.
전체 서버 테스트는 실행하지 않았다. 실제 DB/모델을 사용하는 기존 테스트를 포함하지 않는 지정된 모의 범위다.
Gradle의 기존 deprecated feature 경고가 있었고 빌드는 성공했다.

## 보존·미실행·한계

- 원문 전달·인용 검사·프롬프트, 검색 코드와 기본 설정·거리 필터·활성 20/후보 30 정책을 변경하지 않았다.
- DB 스키마·DRAFT 저장 SQL·기존 체류시간 저장 방식·idempotency 결과 재조회는 유지했다. 기존 데이터는 재검증하거나 마이그레이션하지 않았다.
- 실제 모델 호출 **0**, 실제 검색 실행 **0**, 운영 DB 반영 **0**, 배포 **0**. mock 응답만 사용했다.
- 기본 작업공간의 미커밋 수집기와 평가 확장을 복사·수정·커밋하지 않았다. 기존 검색/계획 평가셋을 실행하거나 새 평가 문항·모델 호출 범위를 정하지 않았다.
- 검색 순위/리랭킹 품질, 단일 LLM 도구 선택, 실제 계획의 시간·동선 품질은 이 결과로 판정하지 않는다. 도구 루프·일정 수정·확정/롤백도 이번 구현에 포함하지 않는다.
- **토큰 예산은 미해결**이다. 다음 실제 LLM 실행 전에 모델·입력 토큰·출력 예약량·context 한도·초과 시 처리 정책을 확인해야 한다. 그 실행의 기존 데이터셋/트랙·case ID·호출 횟수·비용은 실행 전에 별도로 알린다.
