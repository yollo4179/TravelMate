문서 버전: 1 · 실행·작성: 2026-11-01 · 구현 기준: `ba6af60d`의 후속 작업

**이번 22구간에서는 다른 청크를 주로 요약한 오류가 2→0으로 줄었다. 다만 혼합 장소의 경관 귀속 회귀 1건이 생겼다.**
따라서 전체 문맥 오류가 없어졌거나 v5를 운영에 채택할 수 있다는 결론은 아니다. 기본 프롬프트 v2를 유지한다.

## 실행한 것과 고정 조건

저장된 v4 응답 9개를 재사용하고, **명시적 청크 입력 + v5 응답만 9개** 새로 생성했다.
원문·분할·장소 ID·모델 선택·effort `fast`·8192 출력 한도·스키마·`tools=[]`·검증 버전 v2를 고정했다.
9개 응답의 실제 모델은 모두 기존과 같은 `perplexity/sonar`였다. 이름 일치는 공급자 내부 모델 스냅샷 고정을 뜻하지 않는다.

바뀐 요청 필드는 `input`과 `instructions` 두 가지다.
입력에는 코드가 정확히 자른 `span.chunk_text`를 더하고 v5는 그 원문을 직접 읽도록 지시한다.
요청 준비·전송 후 검사에서 그 외 필드가 그대로임을 확인했다.
**입력 형식과 지시문을 함께 바꾼 검수**이며 입력 추가만의 효과나 이전 오류의 원인을 분리해 입증한 실험은 아니다.
별도 분할 후보 136개는 적용하지 않았다. 기존 22구간을 그대로 사용했다.

새 웹 검색·검색 지표 측정·임베딩·리랭킹·DB 적용·서비스 배포는 실행하지 않았다.
이전 v4의 검색 21/22를 v5의 검색 결과로 옮겨 쓰지 않는다.

### P08-S01을 회귀로 판정한 이유

원문은 첫 경관을 감상한 **뒤** 청담도로공원으로 이동한다. 제목에도 두 공원이 함께 있다.
v4는 경관 감상이 삼성해맞이공원에 속한다고 명시하고, 대상 ID 394는 `mentioned`로 보존했다.
v5는 첫 경관을 “이곳”의 전망이라고만 설명하면서 ID 394를 `subject`로 반환했다.
즉, 다른 장소의 전망이 대상 장소의 검색 문맥으로 연결될 수 있는 조합이다.

같은 청크 뒤에는 대상 공원 동선도 있어 **subject로 바뀌었다는 이유만으로 모든 혼합 청크를 오류 처리하지는 않는다.**
이 사례에서는 문맥의 경관 소유 장소 구분까지 함께 사라졌으므로 귀속 회귀로 판정했다.
검수의 `wrong_place_attribution`과 `mixed_place_attribution_regression`은 이 **같은 1건**이며 두 건으로 더하지 않는다.
형식·오프셋·장소 ID 검증은 이 의미 오류를 거르지 못했다.

- P09-S01은 대상 주차와 다른 공원의 산책·경관이 섞여, 관찰마다 장소를 명확히 나누지 못하는 위험이 남는다.
- P01-S02의 도보 접근 서술과 인용된 자동차 전용 안내 사이 충돌은 이번 문맥도 모두 보존하지 않았다.
