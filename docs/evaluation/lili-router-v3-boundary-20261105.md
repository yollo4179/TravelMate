### 자동 검사가 놓친 의미 오류

- `V3-D-outside-catalog`(r4): "해운대 근처로 보고 싶은 거지? 카드에 장소들은 이미 보이고 있어서…"라고 답했지만 카드에는 서울 장소만 있었다. 카탈로그에 없는 지역을 찾은 것처럼 말했다.

## 실측 중 드러난 운영 문제

1. **크레딧 소진이 원인 불명으로 기록됐다.** 서버가 공급자 오류 내용을 숨기고 "호출 실패"만 남겼다. HTTP 상태와 오류 종류(type, code)만 관측 기록에 남기도록 바꿨고, 그 뒤 원인이 `429 insufficient_quota / credit_balance_exhausted`로 확인됐다. 오류 메시지 본문은 입력 일부가 담길 수 있어 남기지 않는다.
2. **호출 하나가 실패하면 비용 안전장치가 그 묶음의 남은 호출을 모두 막는다**(의도된 동작). 그런데 막힌 호출이 "토큰 계산 실패(`COUNT_UNAVAILABLE`)"로 기록돼 원인을 헷갈리게 한다. 예약 단계가 계산 단계 안에서 실행되기 때문이다. 고칠 후보로 남긴다.
3. **계획 거부 문항이 채점기 문제로 실패했다.** 서버가 즉시 거부하면 응답이 `ERROR / TOOL_FAILED`로 끝나는데 채점기가 이를 미완료로 봤다. 사용자가 쓴 "예산"이라는 낱말도 내부 용어로 잡았다. 둘 다 고친 뒤 r5에서 통과했다.

프롬프트 캐시:
- 요청 종류별 고정 키(`prompt_cache_key`)를 붙이고, 계획 프롬프트의 고정 규칙을 시스템 프롬프트로 옮겼다(고정 부분 969 → 약 1,193토큰).
- 결과는 효과가 거의 없었다.

| 단계 | r1 (키 없음) | c1 (키 있음) |
|---|---|---|
| LiLi 첫 대사 | 캐시 9.8% | 6.3% |
| 추천 설명 | 0% | 0% |
| 계획 생성 | 0% | 0% |

- 같은 라우터 프롬프트가 오전 9시대 반복 실측(gx)에서는 41/55회 맞았고(매번 1,536토큰), 11시대에는 49회 중 3회만 맞았다. 적중이 OpenAI 쪽 배정에 크게 좌우된다. 공식 문서도 키가 적중을 보장하지 않는다고 적는다.
- gpt-5.4-mini는 24시간 캐시 보존(`prompt_cache_retention: 24h`) 지원 목록에 없다.
- 추천·계획은 한 번도 맞지 않았다. 공유 고정 부분이 이 모델의 실제 최소 길이보다 짧은 것으로 보인다(공식 문서는 "설정에 따라 다르다"고만 적는다).
- 캐시 할인으로 줄어든 비용은 실행 비용의 2~4%였다.

입력 줄이기가 더 확실했다.
- 근거 없는 후보를 LiLi 입력에서 뺀 수정(`1865337f`) 뒤 추천 설명 입력이 중앙 5,306 → 2,482토큰으로 줄었다.
- 이어서 인용 가능한 후보에서도 해시 값(장소 하나에 216토큰)과 원문과 겹치는 카드 요약(286토큰)을 뺐다. 이 변경은 아직 실측하지 않았다.

가격 근거: gpt-5.4-mini 입력 $0.75, 캐시된 입력 $0.075, 출력 $4.50 / 1M 토큰(https://developers.openai.com/api/docs/models/gpt-5.4-mini).
