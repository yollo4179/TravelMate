# 근거 2개 고정·문맥 생성 v2/v4 비교 실험 B

문서 버전: 1 · 실행·작성: 2026-10-31 · 구현 기준: `9a894bf8`의 후속 작업

**v4에서 일부 문맥 오류는 줄었지만 검색 성능의 추가 개선은 확인하지 못했다.**
기본 프롬프트 v2를 유지하고 v4는 후속 검증용으로 보존한다. 운영의 근거 2개 채택도 아직 결정하지 않는다.

## 고정한 조건

실험 A의 복수 근거 구현에서 장소별 리랭킹 근거 수를 **2개**로 고정했다.
보존 v2 응답 9개를 대조군으로 사용하고 새 v4 응답만 9개 생성했다.
모든 요청의 지시문 외 필드가 바이트 문자열·JSON 값 기준으로 동일한지 실제 전송 전후에 확인했다.

| 항목 | 조건 |
|---|---|
| 입력 | 같은 기존 장소 ID·원문·source/version·원문 구간·분할 |
| 모델 선택 / 실제 응답 모델 | 양쪽 모두 `perplexity/sonar` |
| effort / 출력 한도 | `fast` / 8192 |
| response_format | 저장된 동일 스키마, 빈 귀속·mentioned 허용 |
| 도구 | 동일한 `tools=[]`, 새 웹 검색 없음 |
| 검증 규칙 | 양쪽 모두 `contextual-validation-v2` |
| 검색 | BGE-M3·기존 BGE reranker, batch 8·autocast_fp16, 근거 2개 |
| 배경 / 장소 후보 / 출력 수 | 동일 449개 장소 스냅샷 / 후보 30개 / 출력 20개 |
| 평가 질문 | 앞 실험의 고정 질문 26개, 그중 답할 수 있는 질문 22개 |

9개 원문 묶음은 각각 따로 활성화했다. 여러 출처를 모두 한 장소에 동시에 올린 운영 실험이 아니다.
프롬프트 변경으로 임베딩이 바뀌므로 후보·대표 근거의 변화는 허용한다. 동일 질문과 파이프라인·배경을 고정한 비교다.
새 질문 확장·리랭커 모델 변경·웹 도메인/기간 필터 변경·원문 재분할은 하지 않았다.

## v4 구현

새 파일 `v4_contextual_prompt.py`를 등록하고 v1·v2·v3와 기본값은 보존했다.

- 각 요청 구간을 독립적으로 처리하고 `source.text[start:end]`의 주제를 먼저 확인하도록 했다.
- 같은 문서의 다른 구간은 장소 식별·대명사 해석·필요한 배경에만 사용하고 경험·경관·평가로 현재 구간을 대체하지 않도록 강화했다.
- 장소와 주차장·화장실·정원·전망대의 관찰을 구분하고, 주소 푸터에 앞부분의 다른 공원 경관을 붙이지 않도록 했다.
- 화장실→야경 구간 이동, 전망→주소 푸터, 편의시설 개선 제안의 일반 예시를 넣었다. 실제 청담도로공원의 구체 ID나 관측된 응답을 예시로 넣지는 않았다.
- mentioned/view_target만 있는 응답과 귀속 보류를 계속 허용한다. 출력 스키마와 hypothetical_questions 비활성 조건은 같다.

이 프롬프트는 이미 확인한 실패 유형을 보고 설계했다. 기존 22구간은 개발 표본이며 독립 시험셋이 아니다.
각 프롬프트의 생성은 한 번이다. 실제 모델 이름은 같지만 공급자 내부 모델 스냅샷·비결정성을 완전히 통제하지 못한다.

## 원문 대조 검수

에이전트가 동일한 22구간을 대조했다. 독립적인 사람의 블라인드 검수가 아니다.

| 유형 | v2 | v4 |
|---|---:|---:|
| 명확한 구간 주제 대체 | 4구간 | 2구간 |
| 다른 공원의 경관을 대상 subject로 귀속 | 1구간 | 0구간 |
| 검색 후보 / 보존 후 검색 제외 | 17 / 5구간 | 17 / 5구간 |

유형은 중복된다. 표의 두 오류 수를 더해 실패 구간 수로 해석하지 않는다.

- **P09-S02 개선:** v2는 앞 구간의 삼성정·조경·한강·롯데타워 감상을 청담도로공원 subject에 붙였다. v4는 현재 구간에 명시된 청담도로공원 주차장 주소만 설명했다.
- **P05-S02 부분 개선:** v2의 앞 구간 화장실 요약이 v4에서 현재 구간의 쉼터·나들목 설명으로 바뀌었다. 다만 앞 구간 1987년 배경을 추가했고 이 구간의 야경 소문·단풍 기대는 생략했다. 완전한 구간 충실성 달성이 아니다.
- **P01-S03 미해결:** 운전자 휴식·동호회·주차 구간에 앞 구간의 자동차 전용·시설 안내를 주로 요약했다.
- **P05-S03 미해결:** 주차 규모·3시간 무료·차량 합류 주의 구간을 앞 구간 야경·단풍 내용으로 설명했다.
- **부분 누락·인접 관찰:** v4 P03-S01은 v2가 보존한 어두움·관리 관련 감상을 생략했고, P03-S02에는 앞 구간의 어두움 관찰을 추가했다. 전체 주제 대체 표와 분리해 메모했다.
- **혼합 원문 유지:** P09-S01의 주차장과 삼성해맞이공원 경관은 한 원문 청크 안에 함께 남는다. 프롬프트만으로 원문 혼합을 해소하지 못한다.

즉, 형식 검증을 통과한 9개 응답이 모두 의미적으로 정확하다는 결론은 아니다.

## 실제 검색 비교

동일 질문 26개 × 두 프롬프트 = 52건을 실제 pgvector·모델로 실행했다.
실험 A의 근거 2개 v2 기준군과 이번 v2의 26개 장소 순위·선택 구간이 모두 일치했다.

| 답할 수 있는 22문항 | v2 + 근거 2개 | v4 + 근거 2개 |
|---|---:|---:|
| 목표 장소가 임베딩 후보 30개에 포함 | 22/22 | 22/22 |
| 목표 장소 1위 | 22/22 | 22/22 |
| 상위 5위 + 올바른 대표 원문 선택 | 21/22 | 21/22 |

Q21 주말·공휴일 주차 혼잡은 양쪽 모두 P08-S02를 선택해 장소 1위를 유지했다.
Q26 무료 주차도 양쪽 모두 P09-S01을 선택했다.
Q14 야경 소문·단풍 기대에서는 양쪽 모두 잘못된 문맥이 붙은 P05-S03이 대표로 남았다.
따라서 명확한 문맥 오류 감소가 이번 표본의 검색 지표 증가로 이어지지는 않았다.

모호한 인과 표현이 있는 Q10을 제외해도 올바른 대표 구간 선택은 양쪽 모두 20/21개로 같다.
다른 장소의 관련성은 전수 판정하지 않았으므로 전체 Precision·Recall·답변 환각률로 표시하지 않는다.
최종 답변과 Spring/Kafka 전달·서비스 전체 지연은 이번 비교에 포함하지 않았다.

## 과금·보존·검증

- 새 Sonar v4 응답 **9개**, 기존 v2 재호출 **0회**. 공급자 usage에 보고된 비용 합계는 **US$0.01505**다.
- 첫 응답 생성 후 Windows의 긴 비교 보고서 경로에서 파일 저장 오류가 났다. 생성 원본·캐시는 이미 보존돼 있었다.
- `GenerationBaseline.write_report`에 별도 출력 디렉터리를 지정할 수 있게 하고, 첫 응답을 재사용해 남은 8개만 호출했다. 완료 실행의 HTTP 호출 8회와 이전 응답 캐시 재사용 1회를 감사 기록에 분리했다. 같은 입력을 다시 유료 생성하지 않았다.
- 비교 계획은 키를 읽거나 HTTP 클라이언트를 만들지 않는다. 실제 실행만 명시한 키 파일을 읽으며, 키나 인증 헤더는 아카이브에 저장하지 않는다.
- 검색 단계는 로컬 `/embed` 19회·`/rerank` 52회다. 이 단계의 Perplexity 호출 0회와 앞 생성 단계의 9회를 구분한다.
- 서버 테스트 60개 통과·기존 통합 테스트 11개 건너뜀, 평가 검사 9개 통과. 별도 실제 DB/모델 검색 52건은 건너뛴 11개 테스트와 합산하지 않는다.
- 기존 원본 72개 파일·계획 대조군 36개 파일의 해시 보존을 확인했다. 임시 스키마 0개, 공개 장소 449개 전체 행의 전후 해시가 같다.

v4는 선택 가능한 실험 버전으로 남긴다. 운영 기본값·기존 벡터·프롬프트 기록을 교체하지 않았다.
이후 장소 경계 분할(C)과 전체 출처 동시 색인(D)은 별도 조건으로 비교해야 하며, 이번 실험 B의 프롬프트만 변경한 결과와 섞지 않는다.
