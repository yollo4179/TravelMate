# 사람 검수 기준

질문과 지역·도시 필터를 모두 읽고, 제공된 동결 장소 원문을 근거로 판정한다.
현재 모델의 추천 순서나 검색 방식은 검수자에게 공개하지 않는다.

| relevance | 기준 |
|---|---|
| 3 | 핵심 의도와 명시한 필수 조건을 모두 만족한다는 근거가 있다. |
| 2 | 핵심 의도에 적합하며 필수 조건을 위반하지 않는다. 일부 비필수 선호만 덜 맞는다. |
| 1 | 주제는 관련되지만 핵심 의도를 충족하지 못하거나 필수 조건을 명백히 위반한다. |
| 0 | 요청과 무관하거나 장소·지역 등 필수 조건을 명백히 위반한다. |
| unknown | 판단에 필요한 근거가 부족하다. 오답 0점으로 바꾸지 않는다. |

- `relevance`는 초기 공란이다. `review_status=pending`을 판정 완료로 취급하지 않는다.
- `evidence`에는 장소 원문의 인용과 필드명을 기록하고 `rationale`에는 판단 이유를 적는다.
- 이용시간·가격·예약·연령·반려동물·접근성은 문구가 없다는 이유로 불가능하다고 판단하지 않는다.
- 실시간 조건을 과거 스냅샷만으로 확정하지 않는다. 추가 출처를 사용했다면 URL·조회일도 기록한다.
- 부정 표현은 실제 요청의 일부다. 선호와 필수 제외 조건을 구별한다.
- 같은 이름의 다른 장소나 중복 DB 레코드는 장소 ID와 본문으로 구별한다.
- 수집 실패·알 수 없는 ID·조건 미적용은 시스템/데이터 문제로 기록한다. 검색 오답으로 대체하지 않는다.
- 검수 전 질문 자체의 명료성·번역·검색 의도와 DB 범위를 확인한다. 수정 시 새 버전을 만들고 결과를 보기 전에 다시 동결한다.
- 두 검수자가 독립적으로 전체 풀을 판정하는 방식을 권장한다. 어려우면 사전에 정한 표본을 이중 검수하고 일치율·이견 조정 내역을 남긴다.
- 최종 판정이 unknown인 후보가 있는 문항은 완전 판정 평균에서 제외하고 누락 수를 공개한다. 결과가 불리하다는 이유로 문항을 제외하지 않는다.

`challenge` 문항에는 정답 없음이라는 라벨을 미리 붙이지 않았다. 지역 밖 요청은 코퍼스 범위와 반환 지역을,
근거 부족 요청은 조건을 확인할 수 있는지와 반환 결과를 별도로 검토한다.
검색 API만으로 Agent의 명확화 질문·거절·최종 발화 품질을 평가하지 않는다.
