# 추천·계획 기능의 메시지 평가 기준

대상은 별도 Planner 모델이 아닌 단일 대화·제어 LLM의 추천·계획 기능이다.
서버가 반환한 type/data, 도구의 이름·고정 인자·선택 ID, 동선·시간은 코드 검사의 대상이다.
여기서는 실제 message와 자유문장 query의 의미만 평가한다.

공통 척도: 3=요구를 근거에 맞게 충족, 2=핵심을 충족하나 경미한 누락,
1=일부만 관련되거나 중요한 누락, 0=핵심 불일치·근거 없는 주장·상태 오인.
적용할 수 없는 항목은 applicable=false, score=null로 기록한다.
각 항목의 이유와 실제 출력·모델에 주어진 근거의 정확한 인용을 남긴다.
없는 주장이나 설명 누락을 지적할 때는 출력 인용을 null로 둘 수 있다.

- intent_alignment: 질문과 이전 대화의 주제, 지역·제외·필수 방문 의도를 이해했는가.
  search_places.query와 recall_memory.query는 같은 뜻의 다른 표현을 허용한다.
- persona_consistency: 주입된 버전의 가이드 성격·관계·말투를 지키는가.
  사용자의 명시적인 말투 변경 요청은 반영할 수 있다.
- grounded_claims: 추천 이유가 실제 후보 원문·전달된 도구 요약으로 확인되는가.
  정적 관광지 소개에서 오늘 예약 재고·운영시간·현재 혼잡·실제 방문을 창작하지 않는가.
  참조 답변의 문장이나 목록 자체를 실제로 검색된 근거로 취급하지 않는다.
- tool_outcome_communication: 장소 목록, 일정 미리보기, 확정 후 반영, 실패를 구분하는가.
  미리보기를 저장 완료라고 설명하지 않고, 순서·시간·동선은 서버 계산 결과에 따른다고 설명하는가.

참조 답변은 가능한 표현의 예시이며 같은 장소를 같은 문장·같은 순서로 나열해야 한다는 정답이 아니다.
골든셋에 알려진 정답 외의 장소를 무조건 오답으로 확정하지 않는다.
실제 도구 결과에 없는 숫자나 사건을 기대 답변에서 가져와 응답을 정당화하지 않는다.
이 점수를 Ragas AnswerCorrectness·Faithfulness의 내장 점수로 표시하지 않는다.
