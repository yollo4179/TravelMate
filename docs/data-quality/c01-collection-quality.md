# C01: TourAPI 수집 품질과 원본 보존

기준은 `develop`의 `fe89b2ee3e16ec05fbb9bb0cd073d1f45c056377`이다.
보존된 C01 수정안을 이 기준에 통합하고, 원본과 가공 결과를 분리해 검증했다.

## 수집 결과의 구분

목록·공통·소개·추가 안내는 공통 응답 클라이언트를 거친다.
HTTP·전송 오류, 공급자 오류 코드, 잘못된 JSON·응답 구조·건수, 빈 양수 페이지,
누락된 식별자, 숫자로 해석할 수 없는 좌표와 불완전한 페이지는 수집을 중단한다.
`TourApiCollectionException`은 `TourApiFailureReason`, 수신한 응답 본문, 원인 예외를 구분한다.
전송 실패처럼 응답 자체를 받지 못한 경우에는 원문을 만들어 넣지 않는다.

성공 코드 `0000`, 유효한 `totalCount=0`, 비어 있는 항목 구조가 확인된 경우에만 정상 0건이다.
추가 안내는 모든 페이지의 건수 일관성을 확인한 후 반환한다.
후속 페이지 실패를 부분 성공이나 빈 프로그램 목록으로 반환하지 않으므로 기존 상세 동기화의
`replaceProgramItems`가 실패를 삭제 요청으로 해석하지 않는다.

## 원본·정규화 값·사유

기존 원본 JSON 필드를 유지하며 검색용 문자열만 별도로 정규화한다.
소개문과 추가 안내의 HTML·공백을 정리하고, 제목과 본문이 유효한 안내를 고정 허용 목록 없이 포함한다.
정규화 결과가 같은 안내는 중복을 제거한다. 소개문 없이 안내만 있어도 검색 본문으로 사용하며,
분류명만 있는 경우에는 임베딩 대상으로 삼지 않는다.

`processRaw`의 반환값에 `processingRecords`를 추가한다.
각 레코드는 입력 `raw_list`·`raw_common`·`raw_info` 문자열, 정규화된 설명·위경도,
좌표 상태와 처리 사유를 별도 필드로 담는다. 입력 JSON을 읽어 만든 문자열은 원본 값이며,
HTTP 응답 전체의 바이트 보관이나 새로운 DB 감사 테이블을 의미하지 않는다.
파싱 실패는 `PARSE_FAILED`, 좌표 문제는 `INVALID_COORDINATES`로 구분한다.
성공은 `INDEXED` 또는 `INDEXED_WITHOUT_SEARCHABLE_CONTENT`로 반환한다.
기존 `skippedWithoutOverview` 필드는 호환성을 위해 유지하며, 검색 본문이 없어 임베딩을 생략한 건수다.

좌표의 누락·NaN·무한대·넓은 국내 허용 범위(위도 32~40, 경도 123~133) 밖 값을 차단한다.
이는 행정 경계 판정이나 좌표 보정이 아니다. 잘못된 좌표와 파싱 실패 원본은 저장·처리 완료 대상에서 제외한다.

## 오프라인 검증

`Server/TravelMate`에서 다음 명령으로 C01 검사만 실행한다.

```powershell
.\gradlew.bat --offline --no-daemon test --tests 'com.yollo.TravelMate.domain.place.source.tourapi.*'
```

검사 153개가 통과했다. HTTP는 `MockRestServiceServer`, 저장소·저장 서비스·임베딩 클라이언트는
Mockito로 대체하며 Spring 서버를 시작하지 않는다. 오류 행렬은 합성 응답이고,
기존 `Evaluation/datasets/v1.4.0/source/snapshot.json`의 원본 449개는 실제 Java 매퍼와 품질 검사로 검증한다.
스냅샷 검사는 원본 값의 유지, 유효한 추가 안내의 반영, 좌표 오류의 저장 차단,
처리 기록과 저장 대상의 일치를 확인하며 실행 전후 파일 바이트도 비교한다.

스냅샷 SHA-256: `410a9c3c46004cb30644455fe9d5ddb01a52a04a700ffe04159605cf94661218`.
실제 TourAPI·모델·검색 호출, DB 연결·변경, 재수집·재임베딩은 수행하지 않았다.
현재 검색 성능이나 공급자 응답의 최신 계약을 실측한 결과는 아니다.
