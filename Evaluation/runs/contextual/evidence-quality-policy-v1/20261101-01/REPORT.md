# 연결 근거의 대표 선택·보류 정책 검증

2026-11-01. 기준 커밋 `c5d0c7bd` 위의 변경이다. 구현 코드는 이 보고서를 포함한 커밋에서 확인한다.
저장된 결과에 새 정책만 적용한 재생이며, 새로운 실제 검색이나 모델 품질 실측은 아니다.

## 해결한 문제와 실제 예시

질문은 **“주변 관광지와 연결된 곳”**이다. 도보·거리·현재 통행 가능 여부를 요구하는 질문으로 바꾸지 않았다.
A/B와 차량 연결공원은 기존 합성 통제 자료의 이름이다. 실제 관광지의 현장 통행 상태를 확인한 사례가 아니다.
청담도로공원은 보존 P09 자료의 선택 근거를 판정한 사례다.
이전 [60행 원문 판정](../../connection-result-audit-v1/20261101-01/REPORT.md)에서 A보다 앞선 차량 연결 장소들도 적합했다.
A의 28위를 오류로 취급하거나 A를 강제로 올리는 변경은 하지 않았다.

문제는 검색·리랭킹에서 선택됐다는 사실과, 그 원문이 질문의 근거가 된다는 사실을 구분하지 않았다는 점이다.
기존 `_complete_recommendation`은 점수로 정렬한 후보를 limit만큼 바로 반환했다.
리랭커는 문장과 질문의 적합도를 평가하지만 그 점수만으로 성공·차단·현재성을 확정할 수 없다.

### B공원: 장소 관련도는 있지만 대표가 차단 기록이었다

B공원은 일반 관계 검색 결과의 29위였다. 대표 기록의 주어는 **A공원에서 B공원으로 가려고 한 방문자**이고,
이동 관계의 출발지는 A, 도착지는 B다.

> A공원에서 B공원으로 이동하려 했지만 공사로 길이 막혀 돌아왔다.

이 기록은 이동 성공이 아니라 차단 경험이다. 다른 선택 근거에는 같은 방향의 성공 경험도 있었다.

> A공원에서 계단을 내려가 B공원까지 걸어갔다.

따라서 B를 관련 없는 장소로 제거하거나 차단 기록을 지우는 대신, 선택된 성공 기록을 대표로 고르고
차단 기록도 같은 설명에 붙였다. 설명에는 **“이동 성공 기록과 통행 차단 기록의 시점 관계가 불명확해 현재 이동 가능 여부를 확정할 수 없습니다.”**를 표시한다.
B가 결과라는 이유로 이 관계를 B→A로 뒤집거나 A의 경관을 B의 특징으로 바꾸지 않는다.

장소의 원래 순위 점수 `0.002540992572903633`은 유지한다. 새 대표 근거의 점수 `0.0014437558129429817`은 별도 필드에 기록한다.
대표를 바꾸기 위해 전체 장소를 다시 정렬하지 않는다. 게시일을 방문일·공사 종료일로 간주하지도 않는다.

### 청담도로공원: 선택 근거가 연결을 뒷받침하지 못했다

청담도로공원(394)의 선택 근거는 흙길·장소 존재에 관한 내용이었다. 다른 관광지로 연결된다는 독립 이동 인용이 없었다.
기존에는 낮은 점수라도 후보 목록에 있으면 반환 가능한 결과가 됐다. 원인은 점수의 절대값보다 **근거 적합성 검사 부재**였다.

새 정책은 이 결과를 `no_verified_connection_evidence`로 보류하고 원래 순위·점수·선택 원문과 사유를 보존한다.
이는 “청담도로공원은 실제로 어디와도 연결되지 않는다”는 결론이 아니다. 현재 선택된 검증 가능한 원문으로 이 질문을 지지하지 못했다는 뜻이다.
일반 관계 검색에서는 원래 30위이므로 이 보류로 현재 최대 20개 응답이 달라지지는 않는다.

### A와 차량 연결 장소: 같은 조건으로 유지한다

“차량으로만 이동할 수 있으며 도보 통행은 금지된다”는 기록은 이번 넓은 연결 질문에 적합하다.
도보 금지를 전체 이동 불가로 바꾸지 않고 원문 제한 조건을 그대로 제시한다.
A도 성공·차단 기록을 함께 표시하지만 순위를 올리지 않는다. 일반 관계 검색의 A는 그대로 28위이고 앞의 27개 순서도 같다.

## 구현 정책

처리 순서는 기존 후보 검색 → 기존 리랭킹 → 선택 원문 근거 판정 → 대표 선택/보류 → 기존 최종 limit이다.
`connection_statements.py`의 전략 레지스트리가 명시적인 긍정·차단 표현과 미판정을 구분하고,
`evidence_quality.py`가 원문 좌표 확인·동일 방향 충돌 대조·대표 선택·보류를 담당한다.

- 정확한 관계 인용·원문 위치·endpoint 귀속이 있는 이동 관계만 검증 근거로 쓴다. 원문을 생성하거나 바꾸지 않는다.
- 기존 선택·리랭킹 근거 안에서 조건에 맞는 긍정 기록을 대표로 고른다. 점수가 낮다는 이유만으로 버리지 않는다.
- 활성 문맥에만 존재하는 미선택 긍정 기록을 대표로 자동 승격하지 않는다. 근거 수 기본 1개, 선택 2·3개와 기존 쌍 예산은 유지한다.
- 후보 전체의 기존 활성 슬롯을 SQL 1회로 읽어 같은 방향의 차단 기록을 대조한다. 활성 20개 밖 자료는 읽지 않는다.
- 차단 대조에는 핵심·보조를 함께 보존한다. 요청한 endpoint 방향은 유지하며 역방향·다른 목적지와 혼합하지 않는다.
- 동일 place_id의 다른 이름 표기는 같은 endpoint로 대조한다. 수단 미상 차단도 겹칠 가능성을 표시한다.
- 현재 통행 상태는 항상 `unverified`다. 충돌이 없다고 현재 이동 가능·안전·가까움을 확정하지 않는다.
- 연결 근거 없음, 긍정 없음, 문장 미판정, 수단 불일치, 활성 자료 변경, 질문 조건 미해결은 다른 보류 사유를 남긴다.

런타임 정책은 판정표·실험 장소 ID·기대 순위를 읽지 않는다. 판정표는 저장 결과의 별도 평가에만 사용한다.
연결 질문의 후처리 범위는 명시적 observation 또는 제한된 한국어 표현으로 정한다. 이 판별은 일반 관계 벡터 검색을 실행하는 조건이 아니다.
기본 chunk-only에서도 연결 질문에는 후처리가 적용된다. **검색 설정을 유지했다는 것과 연결 질문의 응답 동작을 유지했다는 것은 다르다.**

응답은 `evidence_assessment`, `withheld_count`, `withheld_results`, `evidence_quality_scope`와 보류 경고를 기록한다.
보류는 최종 limit 전에 적용하므로 근거 있는 후순위 결과가 빈자리를 채울 수 있다. 보류 결과를 긍정 추천 item으로 보내지 않는다.
Spring이 사용하는 description에도 충돌 설명이 들어가고 완료 원본 JSON에 구조화 이력을 보존한다. 출처/보류 전용 UI는 추가하지 않았다.

## 저장 결과 검증

기존 일반 검색 비교의 9문항 × 2방식 = **18건**을 같은 원래 점수·선택 근거로 재생했다.
동결 계획과 승인 원문·기존 합성 fixture에서 활성 목록을 복원하고 저장 근거의 chunk/context가 그 목록에 있는지 검사했다.
저장 결과에 등장한 일부 근거만 전체 활성 목록이라고 간주하지 않았다. 원래 비교 결과·계획의 해시는 실행 전후 일치했다.

연결 질문의 장소 관련도는 이전 31개 pool qrels, 대표 근거 적합성은 이전 원문 판정을 그대로 사용했다.
같은 에이전트가 결과를 아는 상태로 만든 판정이므로 독립 사람/블라인드 평가가 아니다.
거리나 현재 통행 가능 여부까지 정답인 것으로 계산하지 않는다.

| “주변 관광지와 연결된 곳” | 기존 청크 경로 저장 결과에 적용 | 일반 관계 경로 저장 결과에 적용 |
|---|---:|---:|
| 전체 결과 수 | 30 → 29 | 30 → 29 |
| 장소 관련 결과 / 전체 | 29/30 → 29/29 | 29/30 → 29/29 |
| 대표가 긍정 연결을 지지 / 전체 | 29/30 → 29/29 | 28/30 → 29/29 |
| 보류 | 청담도로공원 1개 | 청담도로공원 1개 |
| 상위 20개 장소·순서 | 동일 | 동일 |
| Precision@5/10/20, NDCG@10 | 모두 1.0 유지 | 모두 1.0 유지 |

분모가 30→29로 줄었다. 일반 관계 경로의 대표 적합성 분자 28→29는 B의 대표를 고친 효과다.
상위 20개는 원래도 적합했으므로 이번 변경을 상위 검색 품질 개선으로 세지 않는다.
전체 18건에서 보류하지 않은 장소의 상대 순서와 점수는 그대로였다.
도보를 명시한 다른 저장 문항에서는 차량 전용 결과가 보류됐지만, 이 문항들에 새 정답표를 만들지 않았으므로 개선 지표로 발표하지 않는다.
경관·주차 문항은 `not_assessed`로 기존 결과를 유지했다. 비활성 보조 근거 문항은 여전히 결과 0개다.

재생 명령과 전체 정책 출력은 [replay.json](replay.json), 입력 해시도 같은 파일에 있다.

```powershell
python -X utf8 Evaluation/tracks/contextual/evidence_quality_replay.py --archive-root C:/ssafy/Travelmate/Evaluation/runs/contextual --output <새-재생-폴더>
python -X utf8 Evaluation/runs/contextual/evidence-quality-policy-v1/20261101-01/audit_code.py
```

전체 원문 아카이브가 필요한 재생이다. 공개 파일만으로 원래 모델 검색을 재현할 수 있다고 주장하지 않는다.

## 남은 한계

한국어 정규식 기반의 제한된 표현 판정이며 범용 의미 함의 검증기가 아니다. 다른 표현의 성공·부정·복합 수단을 놓치거나 보수적으로 보류할 수 있다.
질문 판별도 제한적이라 인식되지 않는 연결 질문은 후처리되지 않는다. 혼합 도보/차량·일부 부정 질문은 조건 미해결로 보류한다.
연결과 경관을 함께 묻는 질문에서는 연결 차원만 확인한다. 모든 복합 조건을 입증하는 정책은 아니다.
정확한 관계 인용이 없는 구버전 자료는 연결 질문에서 보류될 수 있다.
기본 근거 1개가 차단 기록일 때는 활성 문맥의 성공 기록을 자동 승격하지 않으므로 결과 수가 줄 수 있다.

활성 20개 밖의 근거, 잘못된 장소 귀속, 실제 거리·경로·현시점 통행 상태는 해결하지 않았다.
활성 자료 읽기 시 버전/슬롯 불일치는 보류하지만 읽기 후 DB 변경까지 잠그는 방식은 아니다.
활성 문맥 SQL·충돌 설명·보류 이력은 추가되므로 응답 크기와 지연 비용이 있다. 전체 서비스 지연·실사용 질문 성능은 측정하지 않았다.
이번 결과는 저장된 합성 스트레스 실험의 근거 표현 수정이며 일반 운영 검색 품질 향상의 증거로 확대하지 않는다.
