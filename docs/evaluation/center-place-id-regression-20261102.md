# PR #6: 동결 반경 문항의 중심 장소 ID 회귀 수정

`PLR-TM-family_parks-04`의 요청 변환 실패를 수정했다. `area.center_place_id`는 좌표 출처를 나타내는 메타데이터이지만,
`api_contract.search_body()`의 허용 필드 목록에 없어 수집기의 전체 문항 사전 검사에서 `ValueError`가 발생했다.
검색을 시작하기 전 배치 전체가 중단될 수 있는 회귀였다. 수정 전 실제 동결 문항으로 오프라인 재현했다.

## 변경

`center_place_id`를 허용 필드에 추가했다. 서버 전송 본문의 기존 명시적 매핑은 유지한다.
동결 원본과 평가 메타데이터 보존에는 이미 있는 기록 필드를 재사용하므로 새 관측 스키마를 만들지 않는다.

| 항목 | 실제 문항의 값 | 처리 |
|---|---|---|
| 중심 좌표 출처 | `center_place_id: 311` | `selected_inputs.original_input.conditions.area`와 `requested_conditions.area`에 보존 |
| 중심 좌표 | 위도 `37.5206092598`, 경도 `127.1150682209` | 서버 `area.center.lat/lon`에 그대로 매핑 |
| 반경 | `radius_meters: 500` | 서버 `area.radiusMeters: 500` |
| 거리 방식 | `haversine_straight_line` | 기존 좌표 반경 계약으로 처리, 원본 조건 보존 |

ID로 좌표를 조회하거나 포함·제외 필터를 만들지 않는다. 좌표가 없으면 변환은 실패하며,
다른 알 수 없는 area 필드와 범위 밖 반경을 거부하는 기존 검사도 유지한다.
골든셋·manifest·동결 자료와 서버 코드는 변경하지 않았다.

## 오프라인 검증

코드 커밋: `27df85d79fe248275e6fd4fe9d4c9cf65559928a`.
새 회귀 검사는 `Evaluation/tests/test_frozen_search_projection.py`의 6개 검사다.

- 실제 반경 문항의 좌표·반경 매핑과 ID 비전송, 원본 불변을 확인했다.
- 기존 v1.4.0 검색 85문항을 `SEMANTIC_ONLY`·`RERANKED`로 각각 변환했다. 170개 본문 변환이 모두 성공했다.
- 중심 ID만 있고 좌표가 없는 입력과 알 수 없는 area 필드는 계속 거부한다.
- 기존 문항 2개·두 순위 모드의 모의 배치에서 사전 변환, 입력 해시, 원본 보존, 요청·응답 기록 검증을 확인했다.
  외부 HTTP 전송은 차단했고, 실제 검색·모델·judge·관측 서비스 조회/게시는 0회다.

기존 125개에 새 회귀 6개를 더한 수다. 동결 파일이나 줄바꿈 설정을 수정하지 않았다.

그 5개를 코드 실패로 분류하지 않는다.

## 대화 이력과 실행 가능 여부

본문 변환 성공은 모든 조건의 지원이나 검색 품질 통과를 뜻하지 않는다.
85문항 중 65개는 현재 독립 검색 계약으로 조건을 표현할 수 있고, 20개는 `conversation`이 미지원이다.
**해당 반경 문항에도 대화 이력이 있다.** 원본 이력을 제거하거나 적용한 것으로 표시하지 않는다.

모의 배치에서는 앞선 일반 문항의 두 모드가 MOCK으로 완료되고, 반경 문항의 두 모드는
`unsupported_original_conditions` / `conversation` 사유의 `not_run`으로 보존됐다.
배치는 `partial`이며 실제 HTTP 응답·순위를 만들지 않는다. 반경 ID 회귀와 이력 지원은 별도 판정이다.
