## 사용자가 지정한 요구사항

- 기존 TravelMate 문서와 구현을 기본으로 확장합니다.
- 의미 기반 검색 → Top-K → 1개 또는 여러 장소의 자동 생성·배정 흐름을 지원합니다.
- 리뷰 답변·일기·대화의 의미를 분석합니다. 명시적으로 말한 취향은 자동 저장하고, 추론한 취향은 사용자 확인 후 장기 기억에 반영합니다.
- 나만의 투어 가이드 여자친구와 텍스트·STT·TTS로 여행을 관리합니다.
- 장소 추가·삭제·배정 등 계획 변경을 롤백할 수 있어야 합니다. 계획 롤백이 취향 기억까지 되돌리지는 않습니다.
- 실제 카메라 화면에 가이드 아바타를 합성해 함께 찍고, 여행별 사진 앨범 목록에 저장·관리합니다.
- 대화·음성으로 만든 일정 변경안을 보여주고, 음성이나 버튼으로 확정한 후 반영합니다.
- FastAPI가 DB에서 후보를 직접 조회하고 쿼리 임베딩·리랭킹·최종 추천 목록을 한 검색 요청에서 처리합니다. Spring은 인증·사용자 Context·계획 반영을 관리합니다.
- 리랭커 추론을 GPU 반복 실행 약 9.95초에서 약 0.5초 이하로 줄이는 것이 사용자 목표입니다. 구조 이전 자체가 속도 목표 달성을 의미하지 않습니다.
- 지정되지 않은 범위·기준은 질문 후 확정합니다. 아래 설계안은 구현 완료나 미정 정책의 승인으로 간주하지 않습니다.

## 확정 사항과 남은 결정

| ID | 항목 | 현재 상태 |
|---|---|---|
| D-01 | 장기 취향 저장 조건 | **확인됨:** 명시 취향 자동 저장, 추론 취향 확인 후 저장. 리뷰 답변·일기를 주요 근거로 사용 |
| D-02 | 롤백 범위 | **확인됨:** 장소 추가·삭제·배정 등 계획 변경만 |
| D-03 | 함께 사진을 찍는 방식 | **확인됨:** 실제 카메라에 가이드 아바타 합성, 여행별 사진 앨범 목록·저장 |
| D-04 | 음성 명령의 최종 반영 | **확인됨:** 변경안을 보여준 뒤 음성이나 버튼으로 확정 |
| D-05 | 보관·삭제 정책 | 대화·일기·음성 원본·사진·기억의 보관 기간, 삭제 전파 범위는 미정 |
| D-06 | 실행 한도 | 현재 검색 Top-K=30은 코드 사실. 새 흐름의 Top-K·기억 조회 수·툴 반복/시간 한도는 별도 합의 전 고정하지 않음 |
| D-07 | 음성·미디어 기술 | STT/TTS 제공자, 촬영 엔진·대상 기기, 파일 저장소·실시간 전송 방식은 미정 |
| D-08 | 생성·배정의 상세 의미 | 새 계획 생성과 기존 계획 빈자리 배정의 구분은 명세서의 해석안. 지원 범위·적용 단위는 확인 필요 |
| D-09 | 검색 서비스 경계 | **확인됨:** FastAPI가 DB 직접 조회·쿼리 임베딩·리랭킹을 통합. Spring은 인증·Context·계획 반영 담당 |
| D-10 | 리랭커 속도 목표 | **확인됨:** 추론 약 0.5초 이하 목표. 평균/백분위·입력 조건·품질 허용 기준은 미정 |
| D-11 | 추론 자원·운영 정책 | 로컬 RTX 4050 Laptop 전용 VRAM 6GB, 운영 GPU는 미정. 모델·정밀도·배치·토큰·기본 모드·fallback 한도는 확인 후 결정 |
