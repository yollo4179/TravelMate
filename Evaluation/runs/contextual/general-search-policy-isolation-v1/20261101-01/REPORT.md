# 일반 의미 검색에서 이동 전용 후처리 분리

2026-11-01. 수정 기준은 `87e06d3e`다. 원문·관계 검색 기반은 유지하고, 일반 검색을 통제하던 이동 정규식 보류·설명 교체를 제거했다.
이번 완료 기준은 이동 정답률 상승이 아니라 **기존 일반·복합 질문의 순위와 선택 근거 보존**이다.
이 보고서를 포함한 커밋의 코드를 기준으로 한다. 이전 정책의 [보고서](../../evidence-quality-policy-v1/20261101-01/REPORT.md)와 블로그는 당시 실험 기록이며 현재 서비스 정책이 아니다.

## 원인과 수정

`87e06d3e`의 `question_requirement`는 '연결' 등의 표현으로 질문을 이동 의도로 해석했다.
이후 독립 이동 인용이 없는 결과를 보류하고, 통과한 결과도 긍정 이동 인용으로 description을 교체했다.
와이파이 연결 질문까지 이동 근거를 요구하게 되고 복합 질문의 관찰 설명도 덮어쓸 수 있는 구조였다.
이동 사례의 제한된 표현 규칙이 범용 의미 검색의 의미 판단을 대신한 것이 문제였다.

| 대상 | 현재 처리 |
|---|---|
| 정규식 질문 분류·강제 보류·성공 판정 | 서비스 호출 경로에서 제거 |
| 정규식 결과로 description 교체 | 제거. 기존 검색·리랭킹이 선택한 설명 보존 |
| 활성 문맥 추가 조회 | `_retrieve_quality_context` 제거 |
| 과거 이동 정책 | Evaluation의 별도 오프라인 실험으로 이동 |
| 불확실성 기록 | 각 item의 `evidence_assessment.status=not_assessed` |
| 원문·출처·인용 좌표·귀속·방향·조건 | 기존 검증과 선택 근거 그대로 보존 |
| 관계 벡터 검색·리랭킹·거리·기본값·상한 | 유지 |

`not_assessed`는 질문의 의미 적합성, 이동 성공, 현재 통행 상태를 자동 평가하지 않았다는 뜻이다.
원문 보존·좌표 검증을 통과했다는 사실과 의미적으로 적합하다는 사실은 다르다.
단순 표현 일치로 성공을 확정하지 않고, 미판정을 근거 부족·장소 자체의 부적합으로 바꾸지 않는다.
이 상태가 사용자용 UI에 새로 표시되거나 응답 생성기의 해석까지 검증된 것은 아니다.

기존 `evidence_chunks` 안의 `content_kind`·`place_refs`는 관찰의 내용과 주체를 보존한다.
`relations[].evidence`·origin/destination·importance·conditions는 관계의 인용·방향·비중·제한을 별도로 보존한다.
선택된 차단 원문도 해당 기록으로 남기며 긍정 기록으로 재작성하지 않는다.
이번에는 새 관계 종류나 의미적 충돌 탐지기를 추가하지 않았다. 선택되지 않은 모든 차단 기록을 추가 수집하지도 않는다.

관계 벡터가 선택되면 그 관계의 원문으로 리랭킹하는 기존 표현은 유지한다.
따라서 결과 설명에 이동 내용이 등장할 수는 있지만, 정규식 후처리가 관찰 설명을 이동 설명으로 일괄 교체하지 않는다.
근거 수 기본 1개·선택 2/3개도 유지하므로 복합 질문의 모든 근거가 항상 선택되는 것은 아니다.

## 과거 정책의 실험 분리

정규식 정책과 단위 검증은 `Evaluation/tracks/contextual/experiments/connection_quality`로 옮겼다.
서비스 앱은 해당 모듈을 import하지 않는다. Docker의 앱 COPY 범위에도 Evaluation은 들어가지 않는다.
운영 설정·환경 변수·요청 옵션은 새로 만들거나 변경하지 않았다.
과거 정책 재생은 아래처럼 별도 실험 선택이 있어야 실행된다.

```powershell
python -X utf8 Evaluation/tracks/contextual/evidence_quality_replay.py --experimental-policy movement-regex-v1 --archive-root <로컬-아카이브> --output <새-실험-폴더>
```

이 명령은 과거 규칙의 재현용이며 현재 서비스의 의미 평가가 아니다. 이번 비교를 위해 이 정책을 다시 실행하지 않았다.
실험의 성공/차단 라벨도 정규식 추정이지 사실 확정이 아니다.
과거 단위 검증 11개는 오프라인 호환성 검사로 따로 실행했으며 서버 회귀 통과 수에 합산하지 않았다.

## 검증: 저장된 18건과 일반·복합 질문

[replay.json](replay.json)은 기존 비교의 9질문 × 2검색 방식 = 18건을 사용한다.
원래 `comparison.json`·`comparison-plan.json` 해시를 공개 manifest와 비교하고 실행 후에도 같은지 검사했다.
기존 전체 리랭킹 결과를 실제 `_to_result_item`에 전달해 반환 형식을 비교했다.
수집되지 않은 카탈로그 필드는 양쪽에 같은 대체값을 넣었으므로 그 필드의 실제 운영값을 검증한 결과는 아니다.

비교 기준은 후처리 전 `c5d0c7bd`와 정책 적용 결과가 저장된 `87e06d3e`다.
18건 모두 **기존 순위·점수·description·선택 evidence_chunks**를 보존했다. 새 item의 미판정 상태만 추가된다.
`_complete_recommendation`, 후보 검색, 추가 근거 조회, 색인, 초기화 메서드의 AST도 후처리 전과 동일하다.
원문/좌표·관계/귀속·선택/랭킹·검색 전략 관련 파일 9개는 `87e06d3e`와 같다.
이 검사는 반환 단계의 저장 결과 재생과 코드 보존 확인이며 새 검색·새 리랭킹 실측이 아니다.

| 저장 질문 | 이전 정규식 정책 → 현재 전체 순위 목록 | 해석 |
|---|---|---|
| 주변 관광지와 연결된 곳 | 양쪽 방식 29 → 30개 | 보류했던 청담도로공원 복원. 기존 상위 20개는 동일 |
| 목적지/도보/야경+이동 문항 | 기존 방식 1 → 30개, 관계 통합 방식 2 → 30개 | 강제 보류 제거의 결과이며 30개 모두 적합하다는 판정이 아님 |

실제 응답 limit은 그대로 최대 20개다. 위 숫자는 보존된 전체 순위 목록이며 API 반환 개수와 다르다.
기존 판정의 관련성 지표를 새 정확도로 다시 발표하지 않았다. 부적합 후보를 다시 남긴 부분도 의미 평가 문제로 드러낸다.

새 코드 회귀 7개는 실제 완료 메서드를 모의 후보·점수로 실행한다.

- 와이파이/인터넷 연결: 리랭킹·semantic-only 모두 이동 정책 보류 없이 반환.
- 부정·조건부·긍정 인용: 원문 유지, 상태는 모두 의미 미판정. 성공 라벨 생성 없음.
- 야경 관찰 청크와 별도 이동 청크: 근거 2개 모드에서 둘 다 보존.
- 야경+이동 혼합 청크와 차단 기록: 설명의 야경 보존, 별도 차단 원문·조건·출처·좌표도 보존.
- 차단 기록이 대표인 경우: 임의의 긍정 기록으로 교체하지 않고 미판정으로 남김.

## 남은 문제와 실행 경계

B공원은 기존 점수상 차단 기록이 대표인 문제가 그대로 남는다. 성공·차단 기록이 선택됐다면 두 원문을 함께 반환하지만
어느 기록이 현재 상황인지, 무엇이 질문의 대표 근거여야 하는지 자동 확정하지 않는다.
청담도로공원도 연결 근거가 부족하다는 기존 판정이 남는다. 이번에는 정규식으로 제외하지 않는다.
A의 28위를 올리지 않았고, 도보·차량 관계의 적합성을 정규식으로 재판정하지 않는다.

선택하지 않은 상충 기록, 활성 20개 밖 자료, 잘못된 장소 귀속, 실제 거리·안전·현재 통행 상태는 해결하지 않았다.
기존 거리 구현을 유지했으며 PostGIS 신규 변경은 없다. 범용 근거 적합성 평가와 근거 기반 응답 생성은 후속 과제다.

실제 검색 재실행·임베딩/리랭커/Perplexity 호출·유료 호출·운영 DB 반영·배포는 **모두 0**이다.
검증용 내부 네트워크와 tmpfs DB만 사용했다. 테스트의 모의 응답에 있는 공급자 모델명은 실제 호출을 뜻하지 않는다.
환경·정리는 [environment.json](environment.json), 실행/공개 텍스트 해시는 [publication.json](publication.json)에 기록한다.
