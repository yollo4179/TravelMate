# 2026-11-01 명시적 원문 입력과 분할 후보 준비

- 작업 브랜치 `feat/contextual-explicit-span-input`, 기준 `20f6c08c`의 후속 작업이다.
- 코드가 보존 원문의 Unicode 코드포인트 구간을 잘라 `span.chunk_text`로 전달하는 선택 입력 계약을 추가했다.
- 기존 위치 입력·기본 v2·v1~v4 지시문·스키마·분할·검색 설정을 유지했다. 새 입력의 기록·캐시·무료 재검증을 지원한다.
- 입력만 바꾸는 비교는 별도 검증기로 제한하고, 기존 지시문 외 필드 동일 검증은 그대로 유지했다.
- v5는 명시적 청크를 직접 읽는 지시문이며 명시적 입력을 필수로 요구한다. 실제 품질은 아직 검증하지 않았다.
- 저장 v4 기록 9개·22구간으로 요청을 준비하고 원본 36개 파일 해시·청크 원문 일치를 확인했다.
- 구조 기반 분할 후보 136개를 별도 파일로 만들었다. 원문/부모 구간을 보존하며 새 문맥·장소 역할을 복사하거나 색인하지 않았다.
- 부모 경계 잘림·주어 생략·과도한 분할·장소당 20개 상한 누락은 미해결이다. 장소 의미 경계 검증과 전체 출처 동시 색인은 후속 과제다.
- 서버 검사 68개 통과·통합 11개 미실행, 평가 검사 9개 통과. 테스트는 모의 HTTP를 사용했고 실제 API·검색 재실행·DB 쓰기는 0회다.
- 처음 샌드박스에서 임시 폴더 접근 오류가 있어 권한을 갖춰 테스트를 완료했다. v5 필수 입력에 맞게 기존 전체 프롬프트 역할 검사를 갱신했다.
