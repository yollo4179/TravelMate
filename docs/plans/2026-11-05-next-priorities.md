## 3. 이동시간과 일정 설계안 (N-2)

### 원칙

- 2시간 같은 여행 가능 시간은 **보장 약속이 아니라 장소를 몇 곳 고를지 정하는 예산**으로 쓴다.
- 고른 장소의 **방문 순서는 이동시간이 가장 짧은 순서**로 정한다. 요청 형식의 `objective`(`DISTANCE`/`DURATION`)가 기준이다.
- 결과에는 "예상 1시간 50분, 이 중 도보 약 25분(추정)"처럼 예상 시간과 출처를 함께 보여 준다. 예상이 예산을 넘으면 우선순위가 낮은 선택 장소를 빼거나 넘는다고 알린다.

### 구조

장소를 노드로, 장소 사이 이동을 간선으로 두는 그래프 방식이다.

```mermaid
flowchart LR
    A[PostGIS<br/>반경 안 후보 추리기] --> B[의미 검색·리랭킹<br/>목적에 맞는 장소]
    B --> C[이동시간 행렬<br/>후보 사이 최단 이동시간]
    C --> D[일정 선택<br/>시간 예산 안에서 장소 선택<br/>+ 가장 빠른 순서]
    D --> E[LLM<br/>선택된 일정의 근거 설명]
```

| 역할 | 담당 |
|---|---|
| 장소 사이 이동시간 | 다익스트라(pgRouting + OSM 보행 도로망) 또는 경로 API |
| 장소와 순서 선택 | 일정 선택 모듈. 장소는 최대 6곳이라 순서를 모두 비교해도 720가지다 |
| 의도 해석과 설명 | LLM |

### 이동시간 값의 층

| 층 | 방법 | 출처 표시 |
|---|---|---|
| 1. 기본 추정 | pgRouting으로 OSM 보행 도로망 최단 경로. 도로망이 없으면 직선거리 × 우회 계수 | `ROUTED` / `ESTIMATED` |
| 2. 실측 보정 (나중) | 동의한 사용자의 실제 이동 기록이 충분히 쌓인 장소 쌍만 기본 추정을 보정 | `OBSERVED` + 표본 수 |

실측 기록만으로 시작하지 않는 이유:

- **표본이 부족하다**: 종로 장소 약 400곳이면 장소 쌍이 약 16만 개다.
- **이동과 체류가 섞인다**: 가다가 들른 시간도 이동시간처럼 기록된다. 도착과 출발 기록을 따로 받아야 한다.
- **위치 기록에는 동의가 필요하다.**

지금의 구간당 15분은 1층이 생기면 대체한다.

## 4. 우선순위 (확정)

| 순위 | 항목 | 이유 |
|---|---|---|
| 1 | **N-1 평가 사례 확장** (N-5 포함) | 기능을 더 만들기 전에 LiLi가 실제로 어디서 실패하는지 알아야 한다. 기존 인프라를 그대로 쓰고, 이제 10문항 1회가 약 1.5분이다. 30~50문항 경계 세트는 원래 목표이기도 하다 |
| 2 | **N-2 이동시간 1층** (pgRouting + 행렬 + 일정 선택) | 계획 품질에 직접 영향을 준다. OSM 데이터 적재와 pgRouting 설치가 필요한 큰 작업이다. 1번의 계획 사례로 전후를 잴 수 있다 |
| 3 | N-3 인용 오류 구분 | 1번에서 발생 빈도를 본 뒤 정한다 |
| 4 | N-4 리랭커 지연 | fp16이 가장 큰 수단이지만 검색 점수가 바뀌어 평가 기준선을 다시 재야 한다. 기준선을 새로 잡을 때 함께 한다 |
| 수시 | N-6 사람 검수 | 사용자 판단 |

N-1에 넣을 사례:

- 같은 의도를 다른 말로 표현
- "두 번째와 네 번째 빼줘" 같은 복수 조건
- 추천 → 제외 → 계획 생성으로 이어지는 여러 턴 대화
- 조건 충돌, 결과 없음, 근거 부족
