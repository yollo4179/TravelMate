# 현재 단일 LLM 경로의 기본 평가 예시 v1

`질문 → 서버 검색·리랭킹 → 원문 청크/출처와 함께 LLM → 답변 또는 도구 실행`을 평가한다.
기존 동결 v1.4.0을 변경하지 않는다. 궁궐 두 문항은 기존 case ID·질문·필터·입력 해시를 재사용하고,
나머지는 현재 등록 도구 계약에 맞춘 소규모 경계 사례다. 200문항 전체나 모든 여행 요청의 품질을 대표하지 않는다.

| case ID | 기대 판단 | 기대 결과 |
|---|---|---|
| `PLR-TM-palaces-01` | 직접 장소 안내 | 창경궁 조회에 답하고 원문을 정확히 인용. 추가 도구 없음 |
| `PLR-TM-palaces-03` | 근거 기반 추천 | 왕실 가족 생활공간이라는 요청과 추천 이유를 연결. 추가 도구 없음 |
| `CONV-SOCIAL-thanks` | 일반 대화 | 감사·종료에 반응. LLM이 선택한 도구와 인용 없음 |
| `CONV-CLARIFY-plan` | 되묻기 | planningRequest가 없으므로 필수 조건 요청. 생성 호출 없음 |
| `CONV-CLARIFY-job` | 되묻기 | Job ID가 없으므로 식별 정보 요청. 임의 조회 없음 |
| `CONV-UNSUPPORTED-booking` | 기능 범위 안내 | 확정·예약이 실행됐다고 주장하지 않음 |
| `CONV-SEARCH-exclude-first` | `SEARCH_PLACES` | 실제 사전 검색 첫 장소를 제외 인자에 넣고 재검색. 반영 필터와 반환 ID 확인 |
| `CONV-JOB-owned` | `GET_PLANNING_JOB` | 제공한 본인 작업 UUID로 한 번 조회. 실제 반환 상태 안내 |
| `CONV-PLAN-create` | `GENERATE_PLAN` | 유효한 planningRequest를 사용하며 도구 인자는 `{}`. Job 접수와 완성을 구분 |

각 기대결과는 `decision_type`, 내부 `tool_types`, 실제 `tool_names`, 인자 조건, 응답 타입·출처,
인용 정책, 설명 예시와 의미 검수 기준을 포함한다. 정답은 평가기만 읽는다. 모델에는 native API 요청만 전송한다.
문장 예시는 글자 일치 정답이 아니다. 질문에 답했는지, 선택 이유가 원문으로 뒷받침되는지 별도 검수한다.

서버 사전 검색은 LLM이 선택한 `search_places` 호출로 계산하지 않는다. 일반 대화에서도 현재 서버가 사전 검색을 실행할 수 있으므로,
"추가 도구 없음"은 `MODEL_TURN.toolCalls`와 실제 `TOOL_RESULT`가 없다는 의미다.

원본의 정확한 인용 위치·출처 소속과 설명의 의미 정확성은 다른 기준이다. 실제로 원문에 있는 인용을 붙였더라도
"현재 왕실 가족이 거주한다"처럼 원문이 지지하지 않는 주장을 했다면 의미 검수에서 실패해야 한다.

수집·채점·검수 명령은 [대화 평가 실행 안내](../../tracks/conversation/README.md)를 따른다.
