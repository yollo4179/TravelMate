# 공통 파이프라인·응답 계약·기본 평가 구현

이번 완료 범위는 **공통 소스 구현과 오프라인·모의 검증**이다. 실제 모델 품질·지연이나 운영 적용을 완료한 결과가 아니다.
삭제된 로컬 백업에 의존하지 않는다. 기존 `6244ec6c` 이력 위에서 구현했다.
초기에는 오래된 `origin/develop=b2c21803`을 실제 원격 상태로 오판해 이력 복원 여부를 질문했다. 이는 실행자의 비교 오류다.
기본 fetch refspec은 main만 추적하므로 `git fetch origin develop`은 FETCH_HEAD만 갱신했다. 실제 FETCH_HEAD는 이미 `6244ec6c`였다.
실제 푸시는 `6244ec6c → 44e17a60`으로 이번 구현·기록 두 커밋만 추가했으며 이력 복원·강제 푸시는 없었다.
이후 develop 추적 참조를 명시적으로 fetch해 로컬 HEAD와 원격 HEAD 일치를 확인했다.
과거 WIP 브랜치 전체를 병합하지 않았다. 필요한 LiLi 원본 이미지와 UI 참고 이미지만 Git의 보존 커밋에서 추출했다.

| ONDEVICE TTS | 사용자 답변에 따라 후속 확장으로 보류 | 엔진·모델 미선정, 음성 구현·검증 없음 |

초안 조회는 기존 DB의 `plans.description`과 `pins.memo`를 설명·활동/선택 이유로 보존한다.
DB 스키마 변경은 없다. 생성 때 검사한 구조화 인용은 아직 DB를 통한 재조회 경로가 없으므로
계획의 정식 인용 전달까지 완료했다고 기록하지 않는다.

## 기본 기대 사례

평가 정답은 모델에게 보내지 않는다. 모델에는 실제 요청과 서버가 검색한 원문만 전달한다.

- 창경궁 조회·왕실 가족 생활공간: 원문에 근거해 답하고 인용. 추가 검색 없음.
- 첫 후보 제외 요청: 실제 첫 ID를 제외 인자에 넣고 search_places 한 번. 실효 필터와 반환 ID 대조.
- 생성 조건 없음·Job ID 없음: 임의 도구 실행 없이 되묻기.
- 본인 Job 조회: 실제 UUID로 한 번 조회. 진행과 완성을 구분.
- 유효한 계획 조건: generate_plan의 빈 인자 계약 사용. Job과 DRAFT를 구분.
- 감사·대화 종료: 인용·추천을 억지로 붙이지 않는 반응.
- 미지원 예약·확정: 실행됐다고 주장하지 않음.

합성 9사례의 기계적 검사 통과는 모델 품질 통과가 아니다. 인간 의미 검수는 응답·원문·정확한 기록 해시에 연결한다.
계획은 추가로 필수 장소·중복·순서·체류시간·반경을 검사하고 미확인 교통·운영시간을 통과시키지 않는다.

## 검증 방법

- Java: 대화·OpenAI·독립 검색·초안 검증·근거 전달의 관련 모의 회귀. 외부 API 미사용.
- Python: 대화 평가 27개 + 기존 공통 모듈/격리 실행기 23개. MOCK가 실제 품질로 승격되지 않는지 포함.
- 검색 Python: 실행 가능한 173개 중 141개 통과·DB 통합 32개 건너뜀.
- 별도 기존 모듈 2개는 호스트의 torch/asyncpg 부재로 실행하지 못했다. 통과 수에 포함하지 않는다.
- 기존 Evaluation 전체 회귀 시 SDK MockTransport 검사에서 대기가 지속돼 중단했다. 전체 회귀 완료로 표시하지 않는다.
- 클라이언트: Node 계약 검사 7개, Vite 빌드, 모의 Chromium 텍스트 요청·메타데이터·감정 이미지·모바일 가로 넘침 검사.
- 동결 v1.4.0 원본·골든셋은 수정하지 않는다.

외부 추론·입력 토큰 계산·실제 검색·Perplexity·운영 DB 변경·배포는 모두 0회다.
최종 실행 요약과 검증 수치는 [오프라인 기록](../../Evaluation/runs/conversation-smoke/20261104-offline-01/REPORT.md)에 연결한다.
