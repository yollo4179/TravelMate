## 해석할 때 주의할 점

- **인용 정규화는 이번 실행에서 쓰이지 않았다.** 모델이 낸 인용 3개가 모두 원문과 정확히 같았다.
  - r2의 palaces-01 같은 경우(한자 병기를 뺀 인용)는 단위 테스트(`QuoteLocatorTest`)로만 확인했다.
  - 따라서 이번 10/10이 정규화 덕분이라는 근거는 없다.
- **같은 palaces-01이 r1 통과 → r2 실패 → r3 통과했다.** 10문항 1회 실행의 통과 수는 실행마다 달라진다. 반복 실행으로 변동 폭을 재기 전까지 안정적인 통과율로 보지 않는다.
- **지연 이상값**
  - palaces-01 라우터 호출 22초 중 19.7초는 OpenAI 입력 토큰 계산 요청이었고, 추론은 2.2초였다.
  - 같은 실행의 다른 호출에서 계산 요청은 0.4~0.6초였다.
  - 토큰 계산을 매 호출 앞에 동기로 두는 구조의 위험이 실측으로 드러난 사례다.
  - 이번 수정 범위에는 넣지 않았다. 구간별 지연을 더 모은 뒤 대체 방식(입력·출력 예산 검사 유지 포함)과 함께 정한다.
- **의미 검수 대상**
  - palaces-03 추천 대사는 근거 없는 후보를 이름 없이 "조선 말기 왕실 가족의 생활과 이어지는 곳"으로 묘사했다. 자동 검사는 이름만 찾으므로 통과했다.
  - 계획 초안의 운현궁에는 원문 근거가 없다(평가 원문 근거는 311·378 두 곳뿐).
