## 해석할 때 주의할 점

- **인용 정규화 사용 여부 (정정)**
  - 처음에는 "정규화가 쓰이지 않았다"고 적었다. 추천 답변의 인용 3개만 확인했기 때문이다.
  - 계획 초안의 두 번째 인용은 원문의 "이었으며,␣␣주로"(공백 2칸)를 1칸으로 옮겼다. 공백 허용으로 통과했고 원문 문자열로 저장됐다.
  - 괄호 병기 생략은 이번 실행에서 쓰이지 않았다. r2의 palaces-01 같은 경우(한자 병기를 뺀 인용)는 단위 테스트로만 확인했다.
- **이 실행에 쓰인 `QuoteLocator`에는 결함이 있었다** (커밋 `8e183120`에서 수정)
  - 30자 이하 괄호를 원문과 인용 양쪽에서 모두 지우고 비교했다.
  - 그래서 "입장료(어린이)는"이 원문 "입장료(성인)는"과 일치한 것으로 처리돼, 조건이 바뀐 인용이 통과했다.
  - 수정 뒤에는 공백 길이 차이와 한자 병기 생략만 따로 허용한다. 한글·숫자 등이 든 괄호는 그대로 옮겨야 한다.
  - 이번 실행에서 통과한 인용 5개는 괄호 내용을 바꾸지 않았다. 따라서 결함은 이번 결과에 영향을 주지 않았다.
- **같은 palaces-01이 r1 통과 → r2 실패 → r3 통과했다.** 10문항 1회 실행의 통과 수는 실행마다 달라진다. 반복 실행으로 변동 폭을 재기 전까지 안정적인 통과율로 보지 않는다.
- **지연 이상값**
  - palaces-01 라우터 호출 22초 중 19.7초는 OpenAI 입력 토큰 계산 요청이었고, 추론은 2.2초였다.
  - 같은 실행의 다른 호출에서 계산 요청은 0.4~0.6초였다.
  - 토큰 계산을 매 호출 앞에 동기로 두는 구조의 위험이 실측으로 드러난 사례다.
  - 이번 수정 범위에는 넣지 않았다. 구간별 지연을 더 모은 뒤 대체 방식(입력·출력 예산 검사 유지 포함)과 함께 정한다.
