# 서버 관계 인용 위치 계산·저장 응답 재처리

문서 버전: 1 · 실행·작성: 2026-11-01 · 기준 커밋: `b47b7b73` · 브랜치: `fix/contextual-server-evidence-grounding`

**정확한 인용문이 모델의 위치 계산 오류 때문에 제외됐던 두 청크를 추가 API 호출 없이 복구했다.**
같은 저장 응답에 서버 처리 규칙만 변경한 결과다. 새 v8 프롬프트의 실제 Sonar 판정·검색 성능을 검증한 결과는 아니다.

## 구현과 보존

- 신규 선택 계약 `contextual-server-evidence-v8`의 관계 evidence는 `{"quote": "정확한 원문"}`만 받는다. 관계 위치를 계산하거나 반환하지 않도록 지시하고 출력 스키마에서도 start/end를 받지 않는다. 청크 자체의 source_id/start/end는 기존 서버 분할 좌표를 복사한다.
- 서버는 **해당 출처의 해당 청크 안에서** 원문을 변경하지 않고 정확한 문자열을 찾는다. 한 곳이면 `청크 시작 + 청크 내 위치`, 끝은 `시작 + 인용 길이`로 계산한다. 좌표는 0부터 시작하는 Unicode 코드포인트이며 끝은 포함하지 않는다.
- 0곳이면 `quote_not_found`, 여러 곳이면 `quote_ambiguous`, 공백뿐이면 `quote_empty`로 보류한다. 겹친 중복도 검사한다. trim·유사 일치·공백/줄바꿈/Unicode 정규화·청크 밖 검색·모델 위치로 중복 해소는 하지 않는다.
- 검증 v5 `contextual-validation-v5`, 계산 규칙 `relation-quote-exact-unique-v1`을 기록한다. 처리 결과 `evidence_grounding[]`에 원래 `model_evidence`와 새 `server_span`을 분리해 보존한다. 계산됐어도 참가자·역할·조건 검증은 그대로 수행한다.
- v1~v7 지시문, 기존 출력 스키마, v7 기본 검증 v4는 유지한다. 저장 v7 응답은 명시적으로 검증 v5를 선택할 때만 재계산한다. 요청·원문·응답은 바꾸지 않고 별도 record를 만든다. 재로딩 시 계산 내역까지 보존 응답에서 재현해 변조를 검사한다.
- v7→v8은 출력 스키마도 변경되므로 프롬프트 전용 비교에서 거부한다. 기본 프롬프트 v2·근거 수·후보 수·활성 상한은 그대로다.

## 실제 저장 응답 두 사례

[이전 실행의 원본 설명](../../v7-integration-v1/20261101-01/REPORT.md)을 그대로 보존했다.

| 사례 | 청크 범위 | 모델 반환 위치 | 서버 계산 위치 | 부모 청크 |
|---|---|---|---|---|
| CONTROL | `[0:35]` | `[16:35]` | **`[15:35]`** | 복구 |
| P09 | `[241:283]` | `[263:283]` | **`[264:282]`** | 복구 |

CONTROL 원문:

```text
A공원은 야경이 아름답고, 관람 후 B공원으로 걸어갈 수 있다.
```

```json
{
  "quote": "관람 후 B공원으로 걸어갈 수 있다.",
  "model_evidence": {"start": 16, "end": 35, "quote": "관람 후 B공원으로 걸어갈 수 있다."},
  "server_span": {"start": 15, "end": 35}
}
```

모델 위치로 자르면 `람 후 B공원으로 걸어갈 수 있다.`가 된다. 서버는 정확한 인용을 찾아 첫 글자 `관`을 보존했다.
P09 인용은 `이제부터 계단으로 올라가시면 돼요`다. 기존 `[263:283]`에는 앞뒤 줄바꿈이 포함됐고, 서버는 인용만 있는 `[264:282]`를 계산했다.
두 사례 모두 청크와 출처 연결은 정상이며, 관계 인용 좌표만 달랐다.

| 저장 응답 | 기존 형식 후보 | 재처리 형식 후보 | 추가 보존 | 재처리 제외 |
|---|---:|---:|---:|---:|
| CONTROL | 3 | 4 | 1 | 0 |
| P09 | 15 | 16 | 1 | 12 |
| 합계 | 18 | 20 | 2 | 12 |

이는 **형식 검증 후보** 수다. 새 후보의 의미 품질 승인·DB 활성화는 수행하지 않았다. P09의 다른 귀속 오류를 모두 해결했다는 뜻이 아니다.
기존 공개 보존 명세에 등록된 로컬 파일 **45개**와 명세 파일 해시를 실행 전후 확인했다. 새 요청 폴더의 request/sources/raw_response는 원본 바이트와 일치한다.
[재처리 결과와 원본·처리 record 해시](revalidation.json)

## 회귀 검사와 실행

- 신규 **15개** 회귀 검사: 잘못된 모델 위치 복구, v8 quote-only 스키마, v7 기본 엄격성, 프롬프트 전용 비교 거부, 중복·겹친 중복·없음·다른 청크·경계 밖 인용, 공백·CRLF·이모지·결합문자 보존, 원본 불변·감사 내역 변조 감지, 디렉터리 옵션 오사용 거부.
- 서버 전체 **125개 중 108개 통과·17개 skip**. 실제 DB·모델 환경을 지정하지 않은 통합 검사만 건너뛰었다. 실행은 `python -X utf8 -B -m unittest discover -s embedding-server/tests -v`다.
- 기존 평가 보존 **9개 통과**. 네트워크 없는 Linux/Python 진입점, 읽기 전용 테스트 스냅샷에서 실행했다. 보존 명세에 맞는 줄바꿈 복원은 스냅샷에만 적용했다. 운영·작업 데이터셋은 수정하지 않았다.
- 초기 Windows 기본 인코딩·줄바꿈·경로·미설치 openai 때문에 일반 평가 전체 27개는 통과하지 못했다. 관련 보존 9개는 Linux에서 통과했지만 **일반 평가 전체 통과를 주장하지 않는다**. 실패/성공 로그를 모두 보존했다.
- 첫 컨테이너의 기본 진입점이 모델 로딩을 시도해 해당 임시 컨테이너를 중지했다. 네트워크가 차단돼 모델 다운로드가 진행되지 않았다. 재실행은 Python 진입점을 명시했다.
- 유료 API **0회**, 운영 DB 쓰기 **0회**, 실제 검색 **0회**다. 테스트 HTTP는 합성 MockTransport다.

## 남은 한계

관계 인용이 잘못됐을 때 부모 청크 전체를 제외하는 정책은 유지했다. 관찰의 귀속이 독립적으로 유효할 때 관계만 보류하는 정책은 별도 설계·검증이 필요하다.
서버의 유일 문자열 일치는 인용이 원문에 있다는 것만 보장한다. 참가자·방향·주체·핵심/보조 비중을 모델이 의미상 올바르게 판정했다는 보장은 아니다.
다른 장소 경관의 잘못된 귀속, Top-30 후보 탈락, 장소별 활성 20개 제한은 이번 변경으로 해결하지 않았다.
DB 반영·새 검수 승인·실제 v8 생성·실제 검색 성능 비교도 실행하지 않았다.
