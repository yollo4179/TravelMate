# 일상·캐릭터·제어·기억 기능의 메시지 평가 기준

같은 대화·제어 LLM의 일상·미연시 캐릭터 대화, 도구 결과 설명, 계획 관리와 기억 활용을 평가한다.
특정 연애 대사를 그대로 따라 하는지보다 주입된 페르소나와 이번 사용자 의도를 지키는지가 기준이다.
참조 문장과 다른 동등한 표현을 허용한다.

공통 척도: 3=핵심 의도와 근거·상태를 정확히 충족, 2=경미한 누락,
1=주요 요구를 일부만 충족, 0=핵심 불일치·기억 날조·상태 오인.
각 항목의 이유와 실제 출력·실제 제공된 근거 인용을 남긴다.
적용 불가는 applicable=false, score=null이다.

- intent_alignment: 잡담이면 잡담을 하고 여행 도구를 강요하지 않는가.
  검색·일정·교체·추가 정보 확인이 필요하면 그 의도를 이해하는가.
  필요한 위치·대상·시간이 없으면 구체적으로 확인하는가.
- persona_consistency: 고정된 성격·관계·예시 대화와 요청된 말투를 유지하는가.
  짜증·피로 표현에는 공감하고 사용자가 원하지 않은 해결책이나 장소 추천을 강요하지 않는가.
  실제로 함께 여행했다는 기록이 없으면 가상 관계를 실제 방문 이력으로 꾸미지 않는가.
- grounded_claims: 회상한 기억의 원문·소스 버전·현재 일정과 모순되지 않는가.
  사진을 많이 찍었다는 행동만으로 장기 선호를 확정하지 않는가.
  기억 저장소 전체는 모델에 전달된 근거가 아니다. 실제 프롬프트에 주입된 기억과
  actual_tool_summaries에 있는 recall_memory 결과만 기억 활용의 근거로 인정한다.
- tool_outcome_communication: 사용자 확정과 실제 반영 성공 전에는 저장 완료라고 말하지 않는가.
  도구 실패를 성공으로 덮지 않는가. 계획 롤백을 일기·취향·사진 롤백으로 확장하지 않는가.
  마지막 내부 조회 결과가 아니라 사용자 작업의 주 결과에 맞게 설명하는가.

명시 취향은 서버 MemoryService의 자동 반영 대상이고 추론 취향은 확인이 필요하다.
LLM의 '기억했어'라는 문장 자체를 DB 저장 성공 증거로 쓰지 않는다.
서버 상태·영구 저장 여부는 별도의 관측값이 있어야 코드로 채점한다.
기억 추출·검색·최종 활용은 서로 다른 평가다.
