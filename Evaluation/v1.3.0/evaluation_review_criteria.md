# TravelMate 리뷰에 적용한 평가 기준

사용자가 제공한 「RAG 평가 - Golden Dataset, LLM-as-a-Judge, Ragas」의 검색·생성 분리 원칙을 리뷰 메모에 적용했습니다. 아래 내용은 Ragas 0.4.3 구현을 기준으로 문서의 지표 설명을 보완한 것입니다. 모델 평가 실행 결과가 아니라, 사용자가 검토하고 확정할 기준입니다.

## 현재 검수할 것

- 질문의 의도와 모든 필수 조건을 읽고 후보 장소가 그 조건을 충족하는지 확인합니다. 같은 주제의 장소라는 이유만으로 정답으로 인정하지 않습니다.
- 지역·제외 장소·대화·반경 조건을 확인합니다. 정확한 장소 조회는 올바른 장소 식별로 검색 점수를 부여하며, 실제 생성 답변이 주소까지 안내했는지는 별도로 평가합니다.
- 메모에 인용한 스냅샷 원문이 판정을 뒷받침하는지 확인합니다. 원문에서 확인되지 않는 사실을 현실에서도 없다고 단정하지 않습니다. 외부 출처를 허용하려면 출처와 판정 정책을 함께 기록합니다.
- 답변 불가·추가 질문 20문항은 각각 작성된 통과 행동과 실패 행동으로 판정합니다. 올바른 답변 보류를 관련성이 낮은 답변으로 일괄 감점하지 않습니다.

## 검색 관련도 0~3점

| 점수 | 기준 |
|---:|---|
| 3 | 질문에 직접 부합하고 모든 필수 조건의 근거가 확인됨 |
| 2 | 모든 필수 조건을 충족하는 유효한 대안이며 직접성은 낮음. 상위 시설을 인정할 때는 대상 시설과의 관계도 확인 |
| 1 | 일부 주제만 관련되거나 필수 조건을 뒷받침할 근거가 부족함 |
| 0 | 다른 지정 대상, 무관한 장소, 지역·제외·반경 등 명시적 조건 위반 |

2점 이상을 정답 후보, 3점을 엄격한 정답 후보로 봅니다. 이 점수를 3으로 나눠 Ragas 점수로 사용하지 않습니다. 기존 점수는 이번 변경에서 유지했으며 최종 판정은 사용자 검수로 정합니다.

CSV 19행의 약현성당은 질문 자체가 ‘전체적으로 로마네스크 양식인 벽돌조 성당’을 요구합니다. 원문의 ‘부분적인 고딕 요소’와 ‘전체적인 로마네스크 양식’을 구분하므로 현행 3점과 모순되지 않습니다.

## 실제 시스템 실행 후 평가할 것

| 구분 | 입력 또는 지표 | 적용 방법 |
|---|---|---|
| 검색 | Hit@K, MRR, nDCG@K 등 | 장소별 관련도와 반환 순위로 계산. 미판정 후보를 자동으로 오답 처리하지 않으며 판정 범위와 judged@K를 함께 보고 |
| 검색 | Recall@K | 정답 누락 가능성이 있으므로 현재 판정된 정답에 대한 값임을 명시. 여러 검색기의 상위 결과를 합쳐 검수하기 전에는 전체 정답에 대한 재현율로 주장하지 않음 |
| 검색 | LLM Context Recall | 기대 답변 `reference`의 주장들이 `retrieved_contexts`로 뒷받침되는지 평가 |
| 검색 | LLM Context Precision with Reference | 기대 답변과 각 검색 청크의 관련성을 판단한 뒤 순위를 반영하는 Average Precision 계산. 단순 Precision@K와 구분 |
| 생성 | Faithfulness | 실제 `response`의 주장들이 생성 모델에 전달한 `retrieved_contexts`로 뒷받침되는지 평가 |
| 생성 | Answer Relevancy | 실제 답변이 질문에 답하는지 평가. 답변 보류·확인 질문 문항은 별도의 행동 기준도 사용 |
| 전체 | Answer Correctness | 실제 답변과 기대 답변 비교. 기본 설정은 사실 일치 75%, 의미 유사도 25% |
| 조건 준수 | 필터·제외·반경·대화·실시간 정보 | 일반 Ragas 지표와 별도로 준수 여부를 기록 |
| 성능 | 지연시간·오류율 | 임베딩·검색·리랭킹·전체 요청의 p50/p95, 실패율, 캐시·콜드 스타트 여부를 기록. Ragas 평가 호출 시간은 서비스 지연시간과 구분 |

부분 판정 문제는 Recall뿐 아니라 Precision·MRR·nDCG에도 영향을 줍니다. 같은 문항·판정 범위에서 비교하고 미판정 상위 후보를 우선 검수합니다. 개발 문항으로 조정한 뒤 시험 문항을 평가하며, 같은 시험 점수를 반복 확인하면서 설정을 맞추지 않습니다.

## Ragas 입력 준비

- `user_input`: 질문. 문맥 의존 문항은 이전 대화와 필터를 평가자가 알 수 있도록 입력 표현을 정의하고 모든 비교 실험에 동일하게 적용합니다.
- `reference`: 기존 사람 판정·기대 행동과 원문을 바탕으로 작성한 문장형 기대 답변. 현재 100문항에 작성돼 있으며 새 문장의 작성자는 `reference_provenance`에 Codex로 기록합니다. 장소 ID나 관련도 점수 자체를 답변 문장으로 취급하지 않습니다. 추천형 참조 답변에 알려진 후보들이 서술돼 있어도 모두 반환해야만 검색 정답이라고 판단하지 않습니다. Top-K 정확도와 장소 Recall은 기존 장소 ID 판정으로 계산합니다.
- `reference_contexts`: 사람이 확인한 근거 청크. 지표에 따라 사용하며 모든 LLM 기반 지표의 공통 필수 입력은 아닙니다.
- `response`: 실제 시스템이 생성한 답변.
- `retrieved_contexts`: 리랭킹·중복 제거·부모 문서 확장·길이 제한 등을 거친 뒤 생성 모델에 실제 전달된 문맥. 별도로 리랭킹 전후 장소 ID와 점수도 보존합니다.

리뷰 CSV의 `evidence`는 후보별 판정 근거입니다. 오답 후보의 evidence는 정답 근거로 합치지 않습니다. 골든셋의 `reference_contexts`에는 양성 정답·관련 근거의 인용만 연결하며, `review_notes`를 실제 `response`로 사용하지 않습니다. 실행기는 골든셋의 참조 답변과 별도 API 파일의 실제 응답·검색 문맥을 연결합니다.

## 점수 해석과 재현성

- Faithfulness 0.449를 ‘답변의 약 55%가 환각’이라고 해석하지 않습니다.
- 관련 청크 판정이 모두 0이면 해당 Context Precision 구현의 점수는 0입니다. API 오류·파싱 실패·평가 불가를 검색 실패와 구분하고 실패 건수와 유효 평가 건수를 함께 보고합니다.
- 연도나 지역 조건을 평가자가 놓칠 수 있으므로 명시적으로 검수합니다. Context Recall이 원리상 연도를 감지하지 못하는 것은 아닙니다.
- 점수 차이만으로 리랭킹 역효과나 청킹 문제를 확정하지 않습니다. 전후 검색 결과와 실제 답변을 대조합니다. 한 번에 여러 구성을 바꾸면 개선 원인을 분리하기 어렵습니다.
- 평가 모델·버전·프롬프트·지표 클래스와 가중치·데이터 스냅샷·검색 설정을 기록합니다. 서로 다른 모델 계열을 평가자로 쓰더라도 사람 검수 표본과의 일치도를 확인합니다.
- 초기에는 사람이 검토한 개발 문항 표본으로 평가자와 기준을 점검합니다. 유의미한 차이인지 판단하려면 평균 외에 문항별 변화와 표본 불확실성도 확인합니다.

이번 변경은 273행의 리뷰 메모와 읽기용 설명을 보완했습니다. 기존 관련도·근거·사람 검수 상태는 유지했으며 실제 검색기·생성 모델·Ragas 평가는 실행하지 않았습니다.
