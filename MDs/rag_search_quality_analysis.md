# RAG 기반 장소 추천 시스템 검색 품질 분석 보고서

> **목적**: Kakao API 기반 장소 데이터만으로는 문맥(context)이 부족하여 의미 기반 검색에서 발생하는 문제점을 실제 사용자 스타일 자연어 쿼리로 실험하고 분석한다.
> **실험 환경**: PGVector + BGE-M3 / Qwen3-Embedding
> **평가 기준**: 의미적 유사도 + 실제 사용자 의도 충족 여부 + 지리적/맥락적 적합성

**작성일**: 2026-07-12  
**버전**: v1.0  
**관련 프로젝트**: Travel AI 앱 RAG 추천 시스템

---

## 1. 배경 및 문제 인식

현재 시스템은 Kakao API에서 제공하는 **카테고리**와 **장소명** 정보만을 주로 활용하고 있다.  
이로 인해 다음과 같은 한계가 드러났다:

- 위치 기반 쿼리에서 **실제 지리적 근접성**을 반영하지 못함
- 추상적 의도(예: "역사 공부하고 싶어")를 이해하지 못하고 단순 키워드 매칭에 의존
- 장소 description에 반복적으로 등장하는 패턴(요금, 주차, 화장실 등)이 임베딩에서 과도하게 강한 신호로 작용

---

## 2. 실험 개요

**테스트 쿼리 4종** (실제 사용자 스타일 자연어)

| No | 쿼리 | 쿼리 유형 | 예상 결과 품질 | 주요 문제 |
|----|------|-----------|----------------|-----------|
| 1 | 경복궁 근처 가볼만한 곳 | 위치 기반 | 중 | 지리 필터링 부재 |
| 2 | 역사 공부하고 싶어 | 추상적 의도 | 나쁨 | 의도 이해 실패 + 노이즈 |
| 3 | 공원에서 산책하고 싶어 | 활동 기반 | 양호 | 위치 필터링 부재 |

- 상위 10개 결과에 대해 유사도 점수 + 지역 + 실제 적합성 수동 평가
- "좋음 / 보통 / 문제"로 분류

### 문제 분석

"스키장 리프트권 할인"이라는 명확한 **상업적·특정 목적**을 가진 쿼리임에도 불구하고, 스키장과 전혀 무관한 장소들이 상위에 노출되었다.

**주요 원인**:
- 장소 고유의 의미보다 **description에 공통으로 포함된 패턴**(요금 안내, 주차, 화장실, 할인 정보 등)이 임베딩에서 더 강한 신호로 작용
- "할인", "요금", "이용권" 등의 단어가 description에 빈번히 등장하면서 의미 왜곡 발생
- 순수 의미 기반 검색만으로는 **상업적 의도 + 특정 시설(스키장)**을 동시에 만족시키기 어려움

## 5. 분석 요약

| 쿼리 유형           | 결과 품질 | 주요 문제점                     | 개선 필요성 |
|---------------------|-----------|----------------------------------|-------------|
| 위치 기반           | 중        | 지리적 근접성 반영 부족         | 높음        |
| 추상적 의도         | 나쁨      | 의도 이해 실패 + 노이즈         | 매우 높음   |
| 활동 기반           | 양호      | 위치 필터링 부재                | 중간        |
| 체험 기반           | 좋음      | 비교적 양호                     | 낮음        |
| 상업적·특정 목적    | 매우 나쁨 | description 패턴 과도 영향      | 매우 높음   |

**핵심 한계**:
1. **지리 필터링 부재** — 의미 유사도만으로는 실제 거리 기반 추천이 불가능
2. **추상적 의도 이해 부족** — "공부하고 싶어", "할인 받고 싶어" 같은 표현을 제대로 해석하지 못함
3. **Description 패턴 과도 영향** — 요금·주차·시설 안내 문구가 임베딩을 왜곡시킴
4. **하이브리드 검색 필요성** — 순수 Dense Vector만으로는 한계가 명확함

## 6. 개선 방향 제안 (참고)

- **지리 필터링** 결합 (PostgreSQL PostGIS 또는 별도 거리 계산 레이어)
- **하이브리드 검색** (Dense + Sparse + Metadata 필터링)
- **쿼리 의도 분류** (의도 분류 모델 또는 LLM 기반 전처리)
- **Description 품질 개선** 또는 별도 요약 필드 생성
- **Reranker** 도입 (BGE-Reranker 또는 Cross-Encoder)
