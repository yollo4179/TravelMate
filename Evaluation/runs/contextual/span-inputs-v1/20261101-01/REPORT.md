**원문 전달 방식과 비교 호환성을 구현·검증했다. 생성·귀속·검색 품질은 새로 평가하지 않았다.**
앞 실험 B의 검색 지표 21/22→21/22 결론은 그대로다. 같은 조건의 검색을 반복하지 않았다.

## 구현 범위

- 기존 입력 `source-offsets-v1`은 문서 전체와 위치만 전달한다. 기본값과 과거 기록의 요청·해시는 그대로다.
- 선택 입력 `source-explicit-chunks-v2`는 같은 문서·위치에 코드가 자른 `span.chunk_text`를 추가한다.
  원문 공백·CRLF·emoji·결합 문자를 정규화하지 않는다. 출력 스키마와 원문 구간·귀속 검증은 같다.
- 새 입력 계약을 기록·캐시·무료 재검증에서 지원한다. 입력 문자열 변조는 원본과 대조해 거부한다.
- 입력 형식 비교는 같은 지시문·모델·effort·8192 한도·스키마·원문·분할을 유지하고 청크 원문 추가만 허용한다.
  `comparison_kind=input-format-only`로 기록하며 기존 프롬프트 전용 비교기의 검증을 완화하지 않았다.
- v5는 v4의 위치 계산 지시를 명시적 원문 읽기로 바꾼 선택 프롬프트다. v4 파일과 기본값 v2는 보존했다.
  v5에는 명시적 입력이 필수다. 실제 응답을 생성하지 않았으므로 개선 수치를 붙이지 않는다.

입력 형식만 비교하려면 우선 **v4 위치 입력↔v4 명시적 입력**을 사용한다.
v4의 숫자 위치를 찾는 지시 자체는 그 비교에 남는다.
그 뒤 **같은 명시적 입력에서 v4↔v5**를 비교해야 지시문 효과를 분리할 수 있다.
v4 위치 입력→v5 명시적 입력을 한 번에 비교하면 입력·지시문을 함께 바꾼 실험이다.
이번 작업은 이 단계들의 준비이며 실제 모델 비교가 아니다.

## 분할 후보의 의미와 한계

후보는 기존 부모 청크 안에서 문단·생략 구분선·제목·문장 구분을 사용한다.
보존 원문을 잘라 원문 위치·부모 구간·`structural-boundaries-candidate-v2`를 기록하며, 이어 붙이면 기존 청크와 같다.
`context_text`나 `place_refs`를 복사하지 않고 모든 후보는 `indexable=false`다.
이 후보 파일을 현재 수집·DB 적용 경로에 넣지 않는다.

P09에서 무료 주차 구간 109:145, 삼성해맞이공원 쪽 장미정원 구간 387:432, 주소 구간 817:847이
서로 다른 후보가 됐다. 관측을 분리해서 볼 수 있게 된 것이며 올바른 subject 판정까지 입증한 결과는 아니다.
다른 장소 이름이 생략된 후속 문장은 문맥 해석이 필요하다. 136개를 운영 청크로 채택하면 짧은 조각 증가와
장소당 20개 상한에 따른 누락 문제가 생길 수 있다. 기존 부모 경계에서 잘린 문장도 이 방식으로 복원하지 않는다.
따라서 장소 의미 경계 분할 실험 C나 전체 출처 동시 색인 D를 완료했다고 표시하지 않는다.
