# required 비교 최소 수정 및 기존 category 실패 재확인

**완료: 기존 2문항의 OpenAI strict 검색 도구 연결 검증.** 이번 PR 정리에서는 기록과 파일 배치만 정리했으며 새 실행이나 기존 검사 재실행은 하지 않았다.

기존 두 문항을 새 실행 폴더에서 각 1회 실행했고 모두 `COMPLETED / PLACES`로 끝났다. 두 문항 모두 `category="관광지"`를 직접 선택했으며 서버가 같은 필터를 적용해 결과를 반환했다. 이전의 `category="궁"` 때문에 후보가 0개가 된 문제는 이번 두 문항 실행에서 재현되지 않았다.

이번 실제 모델 평가에서 선택된 분류는 `관광지` 하나다. **8개 분류 전체나 다른 질문·반복 실행의 품질을 검증한 결과가 아니다.** 별도 judge 호출과 자동 수정·추가 실행은 수행하지 않았다. 기존 중계기 오류 실행은 모델 품질 집계에서 계속 제외한다.

## 비교 수정과 원본 보존

기존 중계기의 스키마 비교에만 `schema_comparison_value`를 적용했다. 비교용 복사본의 `required` 배열을 정렬하며, 다른 배열과 필드는 기존 비교를 유지한다. 실제 요청의 JSON 구조·필드·배열 순서·바이트는 다시 쓰지 않는다. 필수 필드의 추가·누락·중복도 무시하지 않는다.

오프라인 검사 12개가 통과했다. 실제 보존 요청과 중계기의 기존 처리 함수를 사용했고 외부 연결은 없었다.

## 평가 서버 반영과 실행 설정

category 스키마·서버 검증과 기존 예산 가드를 함께 포함한 기존 JAR를 그대로 사용했다. JAR SHA-256은 `48b849b79f2381b85fbc1fb131532b720a317d2e85e23f3b4d51f47fe6462c79`이며 이전 배포 확인 결과와 같다. 새 평가 서버 PID `16600`이 새 실행 폴더의 JAR·설정으로 포트 `18080`을 소유함을 확인했다. 실행 후 해당 전용 프로세스를 종료했다.

- 모델: `gpt-5.4-mini-2026-03-17`
- 문항: `PLR-TM-palaces-01`, `PLR-TM-palaces-03`, 각각 1회
- 실제 사용: 추론 4/4회, 토큰 계산 4/4회, 검색 2/2회
- 재시도·계획·judge·추가 문항: 각 0회
- 추론비 상한 `$0.047616`, 토큰 계산 비용 미확인 명시 허용 정책 유지
- 실제 문맥 계산값은 1,507 / 4,115 / 1,523 / 4,283이며, 출력 예약 1,536을 더한 값이 모두 한도 8,192 이내였다.

## 허용값 준수와 필터 선택 적절성

| 문항 | 모델 category | 허용값 준수 | category 필터 선택 적절성 | 적용 범위 | 결과 |
|---|---|---|---|---|---|
| palaces-01 | 관광지 | 준수 | 창경궁 조회의 저장 분류와 일치 | 서울, city 없음, limit 5 | 5개, 창경궁 1위 |
| palaces-03 | 관광지 | 준수 | 왕실 거처인 정답 장소들의 저장 분류와 일치 | 서울·종로, limit 5 | 5개, 기존 정답 장소 4개 포함 |

이 표의 적절성은 **category 필터에 대한 판정**이다. 허용값이라는 이유만으로 검색어 전체나 답변 전체를 통과 처리하지 않았다. 실제 도구 원본 인자와 서버 전달 인자가 동일하고, 도구 결과의 `searchCriteria` 및 검색 추적에서 적용 필터를 확인했다. 서버가 `궁`을 `관광지`로 바꾼 것이 아니다.

### 창경궁 조회

실제 query는 `창경궁 궁궐, 조용한 왕실 공간, 산책 가능한 역사 문화 장소`였다. `category="관광지"`, `region="서울"`, `city=null`, `limit=5`가 적용됐고 제외 ID는 빈 배열, 반경 필터는 null이었다.

결과는 창경궁(378), 창덕궁 낙선재(380), 창경궁 홍화문(379), 덕수궁 돌담길(91), 경희궁공원(17) 순서였다. 최종 설명은 창경궁의 왕실 가족 생활공간 용도와 창덕궁과의 관계를 설명했다. 인용 1개는 전달된 창경궁 원문의 정확한 연속 부분이며 장소·근거·출처 ID도 일치한다.

다만 단순히 창경궁을 찾아달라는 요청에 없던 `조용한`, `산책 가능한` 조건을 모델이 query에 추가했다. category 선택 오류는 해소됐지만 검색어 확장이 과한 관찰 사항으로 남긴다. 검색어나 프롬프트를 수정하거나 재검색하지 않았다.

### 종로의 조선 왕실 가족 거처

실제 query는 `조선 왕실 가족이 생활했던 궁궐과 왕실 거처, 종로에서 둘러보기 좋은 궁과 별궁, 왕실 가족의 생활공간`이었다. `category="관광지"`, `region="서울"`, `city="종로"`, `limit=5`가 적용됐고 제외 ID는 빈 배열, 반경 필터는 null이었다. 세부 유형·관계는 query에 남았다.

결과는 서울 운현궁(208), 창경궁(378), 건청궁(10), 창덕궁 낙선재(380), 종묘광장공원(372) 순서였다. 기존 동결 정답 자료의 관련 장소 4개가 모두 이번 결과에 포함됐다.

최종 설명은 창경궁·낙선재·운현궁의 생활공간 관계를 설명했다. 정식 원문 인용은 창경궁 1건이며 정확한 원문·ID 일치를 확인했다. 낙선재와 운현궁도 설명에 등장하지만 두 장소에 대한 정식 인용은 없다. 전달된 후보 설명에 기반한 언급과 원문 인용으로 뒷받침한 주장을 구분해 기록한다. 답변 전체가 충분히 인용됐다고 판정하지 않는다.

## 보존과 한계

실제 요청·응답 8쌍, 문항별 앱 요청·응답, metadata, 실행 이벤트, 예산 원장, 검색 추적과 비교 변경 내용을 보존했다. 기존 실패 원본과 평가 결과를 덮어쓰지 않았다. 원본·백업 각 83개와 미포함 C05 두 파일을 유지하고 C02·C03은 진행하지 않았다.
